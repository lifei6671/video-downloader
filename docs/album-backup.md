# 图集备份与恢复

已完成的图集与视频共用现有资产、备份空间和操作队列。启用同步后，新下载图集自动登记；已有下载历史中的完整图集会补录到所选空间。只读取应用管理的文件清单，不扫描任意目录。缺少原图或配套视频的图集不会被标记为完整备份。

## 文件与协议

- 每套图集以一个无压缩 TAR 文档备份，原始文件字节不变，不转码。归档包含版本为 1 的 `album.json` 和按清单顺序排列的原图、Live Photo 配套 MP4；原文件名、顺序、尺寸、质量来源及图片/视频对应关系保留。
- 归档格式使用 [tar-rs 0.4.46](https://github.com/composefs/tar-rs)，沿用其 MIT/Apache-2.0 许可。只启用归档读写所需能力，不引入压缩器或外部命令。
- 远端沿用协议 v2 的单个 `media` 引用，`container` 为 `tar`；传输层既有 `video` 主媒体槽位同时承载图集文档。S3 对象名仍使用该槽位的现有布局。`fields.source` 增加 `kind: image_album` 和类型化的 `album_files`，不保存提取器临时 URL。
- S3/R2 复用流式上传、分片、取消、重试及摘要检查；Telegram 以普通文件发送图集归档，禁用视频属性探测和流式播放处理，原图与视频不会经 Telegram 图片/视频转码。
- 整体归档 SHA-256 与字节数进入现有媒体引用，每个成员另有清单中的字节数和 SHA-256。归档头部固定，不受本机路径、修改时间或权限影响。
- 保持现有图集边界：最多 64 张图片，每张图片和每个配套视频最多 32 MiB。只备份下载时实际保存的文件；原图不可用时已保存的高清文件保持原质量标记，不伪称原图。

已有视频对象和引用不迁移，数据库无需新增表。参与图集恢复的设备需要使用支持此格式的新版应用；旧版应用不支持 `tar` 主媒体引用。

## 恢复与本机操作

列表发现及封面读取不下载图集归档。用户点击“下载到本机”或“查看图集”后，先下载到现有恢复暂存目录，验证整体归档摘要，再检查清单、顺序、固定文件名、长度和每个成员摘要。归档内链接、额外成员或路径不匹配均拒绝。通过验证后，将私有暂存目录提交为图集目录；已有同名文件或目录不会覆盖。

本机原图与 Live Photo 使用现有图集浏览器。恢复失败持续显示错误，不显示为完成。恢复提交中断复用现有操作记录，已提交目录通过同一清单与归档摘要复核后接回资产。

释放本机空间及删除只处理经过清单身份校验的成员，不递归删除整个用户目录；用户后来添加的额外文件保留。成员已删除、后续文件被 Windows 占用时，可释放占用后重试清理。已知归档摘要的本机读取直接验证成员，无需重新打包或额外临时磁盘空间。

数据库备份仍只保存数据库快照。它保留图集记录和数据库内图片缓存，但不替代图集媒体上传；只有数据库记录、尚未成功上传媒体的图集，不能在新设备凭快照恢复完整原图或视频。

## 验证

隔离离线测试：`CARGO_PROFILE_TEST_DEBUG=0` 后执行 `cargo test --locked --manifest-path src-tauri/Cargo.toml --lib album_backup -- --test-threads=1`。关闭测试调试信息用于避开此仓库 Windows 大型测试二进制的 PDB 限制，不改变测试断言。

覆盖 S3 两套独立数据库的上传/发现/恢复、原图及 Live Photo 字节一致性、同名目录避让、再次释放和恢复、完整旧历史补录、损坏成员拒绝发布、确定性归档、清单路径与取消、Windows 占用导致部分删除后的重试，以及 Telegram 普通文件发送/重复确认/下载往返。

浏览器入口：开发服务器下打开 `tests/fixtures/background-download.html?scenario=visual-album-backup`，执行 `playwright-cli --session album-backup run-code --filename tests/album-backup.browser.js`。覆盖 1440×900、1280×800、1024×680、云端图集恢复、静态原图、Live Photo 播放、方向键、弹窗边界及持续失败反馈。该浏览器用例模拟 IPC，归档及传输字节由 Rust 用例验证。

真实 S3/R2、真实 Telegram 服务、原生 Tauri 窗口、macOS Intel/Apple Silicon 及安装包验收：`NOT_RUN`。本次验证不使用真实凭据或用户图集。
