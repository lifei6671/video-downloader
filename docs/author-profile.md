# 作者资料

抖音、TikTok、YouTube、小红书和 Telegram 的头像字节保存在 SQLite。Telegram 使用频道身份和频道头像。

- Tauri 返回的 `author_profile` 为可选对象，包含 `id`、`nickname`、`handle`、`kind`、`bio` 和 `avatar_cached`。旧记录可继续显示原有 `author`，历史任务迁移只读本地数据。
- 抖音沿用 DTK 的 `sec_uid` 身份语义，账号名另存 `handle`；TikTok 使用数字作者 ID；YouTube 使用 `UC…` 频道 ID，`@handle` 单独保存。昵称不再统一加 `@`。
- 抖音/TikTok 的 yt-dlp 适配从已有详情响应补充字段，DTK 视频和图集读取已有 Author；不切换引擎、不新增签名算法。
- 抖音和 TikTok 直接从作品详情的 `signature` 提取简介，写入 `authors.bio`。空白或缺失时保留旧简介。普通下载使用已校验的作品回包补齐简介，也能为缺少稳定作者 ID 的旧任务建立关联。全程无需请求作者主页。
- 抖音从作品作者节点读取粉丝、关注和获赞计数，TikTok 按字段优先读取 `authorStatsV2`，其次读取 `authorStats`。年龄仅使用作者节点给出的有效年龄值。平台明确关闭年龄展示时，清除已保存的年龄。抖音地区与 IP 属地分开保存，TikTok 地区仅取作者节点给出的地区代码。以上字段沿用现有作品请求。
- 小红书从笔记详情的 `user` 对象读取 `userId` 和 `avatar`。网页分享链接和 App 短链共用视频及图集的头像缓存流程。
- YouTube 只根据单视频解析得到的频道 ID读取 `/channel/<id>/about` 的频道头像元数据，不枚举频道视频。复用锁定版本 yt-dlp 的页面/缩略图解析能力，并核对频道 ID；网络通过 GuardedRH、使用该平台配置。头像额外允许 `yt3.ggpht.com`、`yt3.googleusercontent.com`。
- Python 引擎的头像资料请求和下载各使用 5 秒网络超时，并使用固定暂存名 `author-avatar`。Telegram SDK 读取小头像的整个阶段限时 5 秒，直接返回图片字节。头像上限 2 MiB，只接受 JPEG、PNG 和 WebP。Rust 校验后按作者保存；身份不足时沿用单作品缓存。远程头像 URL 不进入事件、任务快照或 SQLite。
- 头像是可选资源。资料缺失、网络失败或头像无效时，作品仍可解析和下载。作品预览、下载任务和任务详情通过 `get_author_avatar(taskId)` 读取缓存字节，在署名前显示头像，缺失时显示占位。可用作者昵称或 ID 搜索本地记录。
- 相同作品再次解析时沿用同一作者的本地头像。作品关联到不同作者时读取新作者的头像。移除历史任务或预览时，仍被其他任务引用的作者保留共享头像。单作品缓存沿用原有引用清理规则。
- Telegram 原生 SDK 从已解析的频道资料读取真实标题，写入 `author_profile.nickname` 和兼容的 `author`。频道 ID 用于本地归并，完整 ID 在任务详情和频道主页可查。历史记录缺标题时沿用已有名称或公开用户名，否则显示“Telegram 频道”。解析公开或数字频道链接时，使用同一频道的头像标识读取小头像。下载使用已有头像缓存，历史任务不会自动联网补全。下载或重试可更新已确认的频道名。频道改名后，媒体文档身份和原文件名仍按已有记录识别。

作者字段沿用 JSON Lines v3 的可选资料契约；Telegram SDK 解析缓存使用独立修订，不改变 Python 引擎协议或备份协议。

## SQLite 存储与旧库迁移

- `authors` 以 `(platform, author_id)` 为主键。`kind`、`nickname`、`handle`、`bio`、`avatar` 和 `profile_updated_at` 均为独立列，昵称可按平台查找。同一作者只保存一份共享头像。
- `follower_count`、`following_count`、`likes_count`、`age`、`region`、`ip_location` 为可空列。已存在的作者表在升级前生成 `*.before-authors-v2-*.sqlite`，同次启动有完整旧库备份时复用。未知值保持为空，缺失字段不覆盖已有值，平台返回的计数 `0` 原样保留。年龄有独立的观察时间，防止旧缓存恢复已隐藏的年龄。
- `task_authors` 以 `task_id` 为主键，通过外键关联任务和作者，支持按作者查任务。任务删除时级联移除关联。任务快照保留兼容字段，展示优先使用关联作者的资料。
- 打开旧库时先使用 SQLite 在线备份生成同目录的 `*.before-authors-v1-*.sqlite`。如果同次启动的备份模块迁移已生成完整的旧库备份，复用该副本。备份成功后在同一事务中建表、关联任务和迁移头像，重复启动直接使用已有表。
- 迁移以已有的稳定平台 ID 归并。Telegram 从校验通过的频道消息身份提取数字频道 ID。仅有昵称的历史记录保留原署名。作者简介按已有资料导入，缺失时留空。迁移选用有效的头像缓存，同一作者有多份时优先采用旧抖音批量共享头像，其余按作品缓存时间选最新有效版本。旧表和缓存字节保留供回退。
- 已有作者表的数据库可补关联旧版本后来写入的任务。任务已有稳定作者身份时，补入匹配的旧缓存头像，保留已有共享头像。仅有旧头像缓存的已关联任务也可补入图片，过期的解析预览修订不影响有效头像导入。

点击作品预览或下载任务中的作者昵称打开本地作者主页，显示已有头像、昵称、平台、账号名、ID 和简介。抖音作者主页省略作者 ID，保留抖音号。缺少头像时使用占位，缺失的资料留空。下方显示该作者的本地作品记录，范围为已提交下载且未取消的作品，可切换列表和卡片并使用现有作品操作。两种布局及主页发起的流式播放均按作品发布时间从新到旧排列，缺少发布时间的记录放在末尾，同一时间沿用任务顺序。返回恢复原页的搜索与筛选。有 ID 时按平台和作者 ID 匹配，旧记录按同平台账号名回退。同一个旧账号名匹配多个已确认 ID 时，只显示旧记录。只有昵称且缺少可匹配身份的资料保留普通文字。Telegram 按频道 ID 聚合。

有已保存的粉丝、关注、获赞、年龄、地区或 IP 属地时，在资料行逐项展示。缺失字段不显示标题或占位。

Windows 原生调试窗口使用隔离旧库验证了作者头像、视频与图集的列表和卡片切换，以及从主页打开本地图集。简介、缺失资料、键盘路径、返回筛选和 Telegram 频道归并由模拟 IPC 的浏览器用例验证，覆盖设计规范的三个视口。

可选资料升级使用 Windows 原生调试窗口和隔离旧库验收。确认旧任务、作者关联和头像保留，缺项不显示。向隔离库写入测试值后重启，确认六项资料均显示，包括关注数 `0`，地区和 IP 属地分别标注。模拟 IPC 验证了另一条作品更新同一作者的资料后，已打开的作者主页会同步更新。新字段未做抖音或 TikTok 联网验收。
