# 视频 S3 备份与按需恢复方案

日期：2026-10-30\
状态：M1–M5 实现与离线验收通过，M6 真实 R2 核心闭环及分片重启续传通过；接管与跨平台等验收未完成，见[验证记录](s3-backup-validation.md)\
代码基线：`codex/s3-video-backup`，基于 `v1.9.1`（`2d32959`）\
产品模式：**单设备主写、多设备只读恢复**\
实施任务：[S3 备份实施任务与验收](s3-backup-implementation.md)

## 1. 目标、边界与不可变约定

映取继续以本地文件为第一读取来源。用户启用远端备份后，应用将**自己管理的已完成视频**及可用封面、转录结果备份到用户自备的私有 S3 Bucket，首版以 Cloudflare R2 作为唯一已验证目标。新设备连接同一备份空间，先导入资产元数据；视频只有在播放、外部播放、首次转录或明确点击恢复时才下载。

### 1.1 写入角色

- **主设备（`primary`）**：唯一负责上传媒体、更新云端记录及转录、写入删除标记、清理远端对象的设备。后台自动备份仅在该设备运行。
- **恢复设备（`reader`）**：可列出、搜索、读取元数据、封面和文案，按需下载视频到本机；可清理本机副本。**任何交互和后台恢复路径均不得发送 S3 写请求**，包括写入探针、删除、分片上传与更新 `library.json`。
- 用户在本机选择的角色不等于云端授权。首次初始化写入 `library.json` 的 `writer_device_id` 与本机持久 `device_id` 必须匹配才允许主设备写入。恢复设备推荐使用独立的 R2 只读凭据。
- 同一个备份空间同一时刻只允许一台主设备。首版不支持多主协作、自动主设备选举或自动接管。
- **主设备迁移**只走明确的运维流程：停止旧设备写入、在 R2 管理端撤销旧写凭据并确认生效、用新的写凭据显式接管，条件更新 `library.json` 的主设备身份与世代。旧设备重连后必须检测角色失效并停止写入。首版必须提供可验证的人工接管步骤；图形化接管向导可后置，不能把直接改本地角色当作接管成功。对象存储无法跨对象原子地强制旧设备停写，因此撤销旧凭据是接管前提。

### 1.2 用户操作契约

| 操作 | 主设备 | 恢复设备 |
| --- | --- | --- |
| 新视频下载完成 | 本地立即可用，后台自动备份 | 保持普通本地下载行为，不上传到已连接的只读备份空间 |
| 查看云端列表、封面、标题、文案 | 支持，文字无需恢复视频 | 同左 |
| 播放、外部播放、转录云端视频 | 本地存在直接使用；否则按需恢复 | 同左 |
| 释放本机副本 | 仅删除本机文件，云端记录保留 | 同左 |
| 删除视频及备份 | 记录删除意图，删除本机文件，写云端删除标记并清理对象 | 不提供此操作，不允许通过底层命令绕过 |
| 移除单条下载记录、清空下载历史 | 只删除下载任务；已保存资产、视频文件及备份均保留 | 同左 |
| 本机文件被移动、磁盘断开或在资源管理器删除 | 标记本机不可用，绝不推断为远端删除 | 同左 |
| 云端资产被主设备删除 | 标记禁止再次上传或恢复，保留其他设备已下载的本机副本 | 云端条目退出可恢复列表，已下载副本保留且可作为本机文件使用 |

首版只处理 `video.kind == "video"`、`Task.status == Completed`、已被应用记录的本机视频。图集、任意目录扫描、跨视频物理去重、上传即清理本地、视频边下载边播放、自动删除其他设备已下载副本、多云双向同步均不包含在首版。

**重要语义**：`file_missing` 表示当前下载任务的本机文件缺失，不等于云端删除；`Status::Completed` 表示下载已完成，不等于远端已备份。本机文件状态、备份操作状态和远端资产逻辑状态分别建模。

## 3. 本地数据模型与迁移

本机生成一次 `device_id`（UUID），持久化在本机数据库；所有远端资产独立使用跨设备稳定 `asset_id`。对于旧的已完成视频，允许直接以既有 `Task.id` 作为新 `asset_id`，但必须建立显式映射，并保证迁移可重复执行。远端导入创建 `MediaAsset`，**不得伪造已完成的本机下载任务或本地路径**。

新增或扩展以下关系：

| 数据表 | 主键及核心字段 | 生命周期 |
| --- | --- | --- |
| `backup_spaces` | `space_id`、`library_id`、`endpoint`、`bucket`、`prefix`、`role`、`writer_device_id`、`writer_epoch`、`credential_ref`、`enabled` | 本机配置；每个操作绑定不可变 `space_id` |
| `media_assets` | `asset_id`、平台及作品 ID、原始文件名、媒体规格、`content_sha256`、`content_bytes`、`asset_state`、`task_id NULL`、白名单元数据 | 独立于下载历史；跨设备按 `asset_id` 幂等合并 |
| `asset_local_files` | `asset_id`、`path NULL`、`bytes`、`sha256`、`verified_at`、`local_state` | 仅本机；文件缺失仅改变本机状态 |
| `asset_remote_objects` | `space_id`、`asset_id`、`record_key`、`record_etag`、`record_revision`、`media_key`、`cover_key`、`transcript_key`、`remote_state` | 远端对象索引及条件写基准；随远端同步 |
| `asset_transcripts` | `asset_id`、`content_sha256`、`text`、模型及流水线版本、`completed_at` | 独立于 `video_transcripts.task_id`，支持云端读取、复制、导出 |
| `backup_operations` | `operation_id`、`space_id`、`asset_id`、`kind`、`phase`、`payload_json`、`attempt`、`next_retry_at`、`last_error`、时间戳 | 持久化操作日志、上传分片及恢复暂存信息，终态后按策略清理 |

要求：

1. 使用事务维护资产、下载任务映射和入队意图；迁移支持旧库和多次启动，不能重复生成资产、重写用户现有任务或删除原字段。备份入队与 `Completed` 提交如不能直接共用一次事务，应先保证完成记录持久，再通过启动补扫实现最终入队。
2. `backup_operations` 保存精确的 `space_id` 与原 Endpoint/Bucket/Prefix 身份，配置更换时冻结旧空间未完成写操作，不能自动发到新空间。
3. 操作状态至少有 `pending`、`running`、`retry_wait`、`blocked`、`completed`、`canceled`；`phase` 保存网络操作之前的持久化断点。进程重启把不确定的 `running` 恢复为待核验，不直接假定失败或成功。
4. 本地可用性 `present / missing / restoring / invalid`、云端状态 `not_backed_up / pending / uploading / backed_up / pending_delete / deleted / error` 分别输出，禁止用单一混合状态覆盖。
5. 只对应用管理的文件执行删除或恢复提交；不扫描、删除用户的其他目录。保留现有链接、路径、符号链接及“目标已存在不覆盖”的边界。
6. 远端导入的元数据、文件名、路径、大小及对象键均按不可信外部输入校验；`task_id` 和本机绝对路径不得从远端记录复制回来。

### 3.1 转录兼容策略

既有 `video_transcripts` 继续服务已存在的下载任务和正在运行的识别任务；资产转录使用 `asset_transcripts`，在旧任务转录成功时同步保存，经迁移保留原文案。云端转录以 `asset_id + content_sha256` 标识其关联媒体，`source.path` 和 `source.mtime_ns` 不进入备份。

云端导入已有文案时可直接查看、复制和导出，无须本地视频；“重新识别”才需要 `ensure_local_video`。恢复后的新路径不能使内容摘要匹配的文案误报“源文件变化”。旧任务仍可沿用原来的路径检测，资产级结果只以摘要校验。**恢复设备上新产生的转录结果只保存到本机资产数据库，不向远端写入或覆盖主设备发布的转录对象**。

## 4. 备份空间发现、身份与对象布局

默认对象键前缀：`yingqu/v1/`。配置可以选择其他规范化前缀，始终确保首尾分隔统一、禁止空段、路径越界和前缀混淆。首版不需要在前缀中加入未知的 `library_id`；**固定入口**为 `<prefix>/library.json`，因此新设备只需输入同一个 Bucket 与前缀即可发现库。

~~~text
<prefix>/
  library.json
  records/<asset_id>.json
  media/<asset_id>/<content_sha256>/video.<ext>
  media/<asset_id>/<content_sha256>/<cover_sha256>/cover.<ext>
  transcripts/<asset_id>/<content_sha256>/<transcript_sha256>/transcript.json
~~~

`library.json` 的最小内容：

~~~json
{
  "schema_version": 1,
  "library_id": "stable-uuid",
  "mode": "single_writer",
  "writer_device_id": "primary-device-uuid",
  "writer_epoch": 1,
  "created_at": "2026-10-30T00:00:00Z"
}
~~~

- **创建新库**：主设备使用 `PutObject If-None-Match: *` 原子创建 `library.json`，并回读确认内容与自身标识一致。`412` 时读取已有库，不覆盖。
- **连接已有库**：恢复设备必须成功读取 `library.json` 并校验模式、版本及库身份；只读导入，不改变任何远端对象。库不存在、权限不足、版本过高和网络错误各自提示。
- **写前校验**：主设备检查本机 `device_id`、本地缓存的 `library_id / writer_epoch` 与远端记录相符。写入前后遵守单设备本地串行化，网络发生不确定结果时重新读取云端状态。
- **接管**：经撤销旧写权限的人工授权流程，使用 `If-Match` 按已读取的 ETag 条件更新 `writer_device_id` 和递增的 `writer_epoch`；`412` 停止并回读。不提供依赖本机时间的自动过期锁。
- 变更 Endpoint、Bucket 或前缀视为连接另一个库，必须重新验证 `library_id`，不能直接把旧库队列重定向。
- 记录和视频对象通过 `asset_id` 命名；媒体按内容 SHA-256 使用**不可变版本路径**。同一个 `asset_id` 的元数据更新只替换其 `records/*.json`，无需覆盖大视频对象。

### 4.1 云端记录契约

`records/<asset_id>.json` 是唯一的资产**逻辑可见性入口**；完整媒体上传、封面和转录对象成功后才发布 `state=active`。推荐字段：

~~~json
{
  "schema_version": 1,
  "library_id": "stable-uuid",
  "asset_id": "asset-uuid",
  "record_revision": 1,
  "writer_epoch": 1,
  "state": "active",
  "source": {
    "platform": "youtube",
    "video_id": "example1234",
    "canonical_url": "https://www.youtube.com/watch?v=example1234"
  },
  "title": "作品标题",
  "author": "作者",
  "original_filename": "作品.mp4",
  "completed_at": "2026-10-30T00:00:00Z",
  "media": {
    "key": "yingqu/v1/media/asset-uuid/sha256/video.mp4",
    "bytes": 123456,
    "sha256": "64位十六进制内容摘要",
    "container": "mp4"
  },
  "cover": null,
  "transcript": null
}
~~~

示例中的 `key` 与摘要为结构示意，实际必须使用真实对象键、64 位十六进制 SHA-256 和校验后的值。可选封面和转录为对象引用，携带 `key`、`bytes`、`sha256`、内容类型和转录模型信息。封面和转录路径包含各自内容 SHA-256，使用不可变对象；更新时先上传新对象，再条件发布 record，发布失败时旧记录引用的内容仍可校验。旧版本对象的键随资产持久保留，用于明确删除时逐项清理。转录单独对象用于避免批量刷新元数据时下载全部长文案；点击查看、复制、导出文案时只读取文本对象，不下载视频。

导出采用严格字段白名单：平台、平台作品 ID、规范来源地址、标题、作者、时长/分辨率、完成时间、原始文件名、媒体与可选对象引用。禁止导出 Cookie、代理认证信息、R2 密钥、`device_id` 对应本地路径、临时签名链接、下载进度、平台响应的任意未审查字段及数据库原始任务快照。敏感来源 URL 中的 token/查询参数应按平台已确认的规范化规则处理。

写入规则：

- 首次记录使用 `If-None-Match: *`，已存在记录使用 `If-Match: <record_etag>`；每次成功写入后更新本地 ETag 和修订号。
- `412 PreconditionFailed` 必须回读，已删除则终止更新，修订号不符则按单主设备串行规则核对，不盲目重试覆盖。
- 不以 ETag 当作媒体 SHA-256；对不确定的 `CompleteMultipartUpload` 或 `PutObject` 回读 `HeadObject`，必要时下载校验，不能仅因单次 404 便断言先前在途写入永远失败。
- 云端 `state=deleted` 的记录保留最小墓碑数据，不允许同一个 `asset_id` 被重新创建为活动状态。

## 5. 自动备份、持久队列和传输

~~~text
视频完成文件提交
  -> 持久化资产映射与待备份操作
  -> 后台核验文件与内容 SHA-256
  -> 上传不可变视频对象
  -> 上传可用封面及转录对象
  -> 条件发布 active 记录
  -> 记录 ETag、版本和 backed_up 状态
~~~

- 启用备份时补扫已有完成且本地存在的**视频**，仅根据既有任务记录入队，不扫描文件夹。启动时补扫 `Completed` 而未关联备份操作的资产，覆盖进程在文件提交后退出的窗口；重复执行保持幂等。
- 备份任务通过 Rust/Tokio 有界执行，与现有视频下载并发上限分离。建议初始视频上传并发 1、主动恢复并发 1；主动恢复优先于后台上传。数据库锁只用于短事务，网络和大文件读写不得持有 `Core.inner` 的全局互斥锁。
- 小于 100MiB 的视频允许普通 `PutObject`；达到阈值使用 `CreateMultipartUpload / UploadPart / CompleteMultipartUpload`。初始分片 16MiB，除最后一片外等长。持久化 `upload_id`、目标键、源摘要、分片号、大小、分片 ETag；续传时用 `ListParts` 对账，分片已过期或源摘要变更则终止旧会话后重新上传。中止失败保留清理意图。
- 流式读文件，不把大视频完整载入内存；上传前后校验源文件状态。若传输期间检测到文件替换或内容变更，不能发布 active 元数据。不可变媒体键避免不同版本互相覆盖。
- 可重试错误包括超时、断网、429 和服务端临时故障，采用有界指数退避和随机扰动；权限、签名、配置错误进入 `blocked`，用户修改设置或明确点击重试后继续。
- 传输取消或应用正常退出应尽可能终止 I/O，保留可恢复的操作记录；不能删除仍可能需要的暂存、已上传分片及已提交的视频。上传成功但元数据发布前退出时，以远端核验继续发布。
- 转录完成后只上传新的转录对象并通过条件更新 record；封面缺失允许只备份视频；备份失败绝不改变原 `Task.status=Completed`。

## 6. 新设备发现、元数据与按需恢复

### 6.1 发现过程

1. 校验 `library.json`，确认 `library_id`、模式和版本。
2. 使用 `ListObjectsV2` 分页枚举 `<prefix>/records/`，验证每个对象键为预期的 UUID JSON 名称。
3. 通过列表 ETag 与本地缓存比较，仅重新读取发生变化的记录；首次导入读取全部记录。单页网络失败时保留已导入条目，不因列表缺失推断资产被删除。
4. 按 `asset_id` 幂等合并；`state=deleted` 优先禁用云端恢复；活动记录仅在字段、内容引用和库身份验证后可见。
5. 列表所需的元数据先入库，封面按可见区域按需读取，转录按访问懒加载；**新设备刷新目录不会请求 `media/` 视频对象**。

云端对象缺失、权限不足、校验失败需显示资源异常；不得自动将损坏或不完整视频标为“仅云端可恢复”。

### 6.2 统一恢复入口

新增异步 `ensure_local_video(asset_id) -> PathBuf`，以及按需进度和取消状态。播放、外部播放、首次转录及明确“下载到本机”共用这个入口：

1. 已有本机文件先做身份、文件类型、大小及先前已验证的摘要状态检查；有效则直接返回。
2. 本地缺失时，仅对 `state=active`、具有合法 `media` 引用且库身份一致的资产发起恢复；相同 `asset_id` 的并发请求合并为同一个任务。
3. 使用 S3 `GetObject` 流式写入目标卷下的专用临时文件。保存远端对象键、ETag/内容摘要与下载偏移；网络重试或重启可使用 `Range` 从已验证偏移继续。不支持 Range 或远端版本不符时安全地从头恢复。
4. 校验总字节数、SHA-256、扩展名与已有媒体头规则，再通过“不覆盖已有文件”的原子提交方式落盘；碰到重名使用安全的新名字，不覆盖用户原文件。
5. 文件和数据库提交须有持久化恢复意图：崩溃后能核验已提交文件并补写路径，而非再次下载或留下伪完成状态。
6. 读取远端前、写文件前及最终提交前检查资产删除与取消状态，确保迟到的恢复结果不会把墓碑资产重新变为可恢复。
7. 完成后继续原播放或转录动作。用户关闭播放器弹窗时，晚到的结果只能更新恢复状态，不得自动重新打开窗口。

首版“完整恢复后播放”，不实现边下载边播放。打开文件夹或查看/复制已有转录文案，不应触发视频恢复。对文件移动、磁盘离线、手工删除与本机副本释放统一只调整本机状态。

## 7. 删除、释放本机副本与墓碑

### 7.1 释放本机副本（主设备、恢复设备均可）

在应用管理的本机视频上执行安全文件删除；成功后将 `asset_local_files` 标记为 `missing`，保留 `MediaAsset`、云端引用与文案；失败则保留可重试提示。此操作**不产生任何远端写请求**，也不删除下载历史（可单独清理历史）。

### 7.2 删除视频及备份（仅主设备）

~~~text
持久化删除意图、目标对象清单和操作阶段
  -> 拒绝新的上传、转录发布及恢复；等待或取消同资产在途操作
  -> 删除本机受管理文件
  -> 将记录条件写为 deleted（持久墓碑）
  -> 删除远端视频、封面和转录对象
  -> 对账确认删除完成，保留最小墓碑
~~~

- 本机删除失败，远端删除不继续；如果文件此前已不存在，可将其视为本地删除完成，继续用户**明确发起**的云端删除。
- 本机已删除但离线，操作保持 `pending_delete` 并显示“远端待删除”；重启或联网后继续。绝不把离线删除显示为远端已删除。
- 删除前持久化所有远端对象键和版本，以便记录被墓碑覆盖后仍能继续物理清理。墓碑仅保留 `schema_version`、`library_id`、`asset_id`、`record_revision`、`writer_epoch`、`state=deleted`、`deleted_at`、`delete_operation_id`，去除标题、来源和转录等正文。
- 云端 record 已存在时使用原 ETag 的 `If-Match` 写入墓碑；尚未发布过 record（例如备份仍在队列或上传中）时使用 `If-None-Match: *` 创建墓碑。`412` 必须回读最新状态后按实际存在性重新判定，不直接覆盖。重复的同一删除应幂等成功；墓碑一旦存在，普通备份操作无法对相同 `asset_id` 再发布 `active`。
- 对象删除不存在视为成功；网络、权限和存储服务错误必须保留真实失败状态。删除后按持久化清单对账；未知结果不能直接视为清理成功。扫描并清理本次操作产生的已确认孤儿对象和未完成分片，但不能扫描或删除整个 Bucket。
- 其他设备刷新到墓碑后禁用远端恢复，保留其已有本机副本；不能自动向其他设备执行文件删除。恢复设备没有云端删除按钮，后端也必须拒绝其删除写操作。
- 最小墓碑长期保留，首版不做自动过期，防止旧状态反向导入。若用户要删除整个备份空间，由其在 R2 控制台管理，本应用不提供 Bucket 级删除。

### 7.3 历史操作仍独立

现有下载任务的“删除本地视频”入口，在主设备且该任务已关联启用备份空间时，映射为“删除视频及备份”；即使仍待备份也应停止待上传任务并持久化删除意图。恢复设备的该入口只能删除本机文件。明确“释放本机副本”作为另一独立操作，任何角色均不会因此修改云端。

原有“移除下载记录”与“清理下载历史”语义保持不变：不会同步删除远端，也不会删除本机视频。备份资产列表为独立入口，任务历史被清理后仍能查看、恢复和管理云端资产。

## 8. S3 客户端、安全与 R2 兼容性

选用 Rust 官方 `aws-sdk-s3`，封装当前所需的 `HeadObject`、`GetObject`（含 Range）、`ListObjectsV2`、`PutObject`（含条件写）、`DeleteObject`、分片创建/列表/上传/完成/中止。避免额外的通用多云 SDK 抽象；底层接口须可注入测试替身。

| 配置项 | 首版契约 |
| --- | --- |
| Endpoint | R2 默认 `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` |
| Region | R2 使用 `auto` |
| Bucket | 用户自建私有 Bucket；绝不创建/删除 Bucket |
| Prefix | 默认 `yingqu/v1/`，规范化、绑定库身份 |
| Access Key ID / Secret | 写入系统凭据；数据库仅保存不可逆的引用标识；新设备独立配置 |
| Role | 创建库的主设备 `primary`；连接已有库的恢复设备 `reader` |

- 设置编辑器通过专用 `get_backup_credentials` 命令回填系统凭据，默认掩码，支持逐项显隐；保存后保留输入并恢复掩码，离开编辑器卸载，不持久化到前端存储。普通设置返回、事件、日志、异常均不可回传 Secret。沿用 `keyring` 的系统凭据管理与失败回滚模式，凭据轮换不改变未完成操作的 `space_id`。
- 恢复设备连接验证只能读取 `library.json`、列举/读取记录，不准执行写入测试。主设备在明确选择测试写权限时可对本前缀下随机探针对象写入、读取、删除；探针清理失败须报告并记录待清理对象。
- 主设备至少要具备目标 Bucket 的对象读、写、列举和删除能力；恢复设备使用仅读取/列举的凭据。不能要求用户授予 R2 账户级管理权限。
- 限制 Endpoint 为 HTTPS，首版放行 R2 官方域名；自定义 S3 Endpoint 留配置字段但未经兼容性验证时显式提示。不得通过自定义任意内网目标或重定向泄露凭据。
- 明确处理 Rust SDK 对 `PutObject` 请求校验和的默认行为，按 R2 当前支持的算法与类型测试；不能假设 SHA-256 内容摘要就是 S3 Multipart ETag。
- R2 普通单次上传最大 5GiB；分片至少 5MiB（末片除外）、最多 10000 片；R2 要求非最后分片等长。默认未完成分片可能被生命周期规则自动清理，续传需要处理 `NoSuchUpload`。
- `429`、`5xx`、网络超时按可重试处理；`403`、签名失败、凭据缺失、条件冲突单独归类。条件写与删除之间没有跨对象事务，依赖持久日志和幂等对账。
- 首版 R2 使用标准存储；不提供对象公共访问、预签名链接共享、云端视频转码或缓存 CDN。

## 9. 桌面接口与交互

### 9.1 Rust / Tauri 建议命令

命令名可按现有模块命名约定微调，但输入、角色鉴权和行为边界须保持：

| 命令 | 行为 |
| --- | --- |
| `get_backup_settings` / `save_backup_settings` | 获取脱敏设置、保存配置与凭据；主/恢复角色在后端校验 |
| `get_backup_credentials` | 仅供设置编辑器从系统凭据回填，默认掩码，不进入普通设置摘要、事件或日志 |
| `test_backup_connection` | 接受未保存草稿，只检查读取连接与已有库身份，不保存配置、不创建库、不写探针 |
| `list_backup_assets` / `refresh_backup_assets` | 获取本机资产及远端元数据增量导入 |
| `retry_backup_operation` / `cancel_backup_operation` | 对持久化操作重试或取消 |
| `ensure_local_video` / `release_local_video` | 按需恢复及本机空间释放 |
| `delete_asset_and_backup` | **仅主设备**允许，持久化删除并反馈远端阶段 |
| `get_asset_transcript` / `export_asset_transcript` | 在没有本地视频、没有下载任务时仍能获取并导出文案 |

既有 `prepare_video_playback`、`play_download`、`start_video_transcription` 保留供本地任务使用；云端资产入口的同类操作应先调用 `ensure_local_video`，再复用原有播放/转录执行逻辑，不复制第二套播放器或识别引擎。返回稳定的任务/操作 ID，事件包含阶段、已完成字节、总字节、错误码与修订号；重启后可重新查询。所有删除写 API 检查后端角色及远端库身份。

### 9.2 UI

系统设置增加“远端备份”，复用 `DESIGN.md` 浅色布局与现有表单组件；最少展示角色、连接信息、测试连接、启用状态、待备份数量/体积、失败重试，不扩成素材管理工作台。

备份只在系统设置中开启和配置，不新增“云端备份”主导航。下载任务列表同时展示本机任务和远端发现的资产，支持原有搜索与列表/信息流视图；远端资产使用独立类型，不伪造 Task 或下载完成状态。列表模式任务标题旁、卡片模式封面左下角的空心云朵表示待同步，上传中按真实传输字节自下向上填充；record 成功发布后才变为绿色对号（已备份）。从 S3 恢复使用同步图标，按真实下载字节填充；普通平台下载保留原进度展示。同步按钮不弹出菜单：待上传点击加入既有队列，上传中点击取消；待下载点击恢复，下载中点击取消。卡片按钮背景与播放按钮一致，图标16px。远端错误仅Toast提示并按操作/错误/尝试次数去重，不在列表内联显示。

同步图标直接提供上传/恢复/取消/重试，更多菜单提供释放本机副本与历史移除；主设备另可“删除视频及备份”，恢复设备不渲染该操作。远端错误使用Toast提示，图标悬停保留原因，不在任务行或列表内联显示。新设备启用后自动读取远端清单，浏览/文案不下载视频。清理历史设置本机隐藏标记，保留资产、文件、文本与远端对象，避免历史任务以云端资产重新出现；待删除清理完成前仍保留可见状态。

状态文案只根据真实后端状态呈现：“待备份、备份中、已备份、备份失败、仅云端、恢复中、本机可用、远端待删除、已删除”。失败状态持久化并可重试，错误提示仅使用Toast。恢复的取消、浏览器窗口关闭、键盘焦点与减少动画设置遵守既有规范；用户关闭播放弹窗后，迟到恢复结果不能弹回播放器。

## 10. 首版实施阶段

分阶段可执行任务和测试命令见 [S3 备份实施任务与验收](s3-backup-implementation.md)。

1. **M1 数据与角色**：数据库迁移、稳定资产身份、库发现与主/恢复设备权限；确保旧下载功能不受影响。
2. **M2 S3 与自动备份**：客户端、凭据、测试连接、后台上传、分片续传、任务恢复和历史补录。
3. **M3 只读发现与文案**：恢复设备导入云端列表、封面/转录独立访问、幂等刷新。
4. **M4 按需恢复**：统一本地文件获取、断点下载、摘要校验、原子提交、播放和转录复用。
5. **M5 生命周期与 UI**：释放本机副本、主设备显式删除与墓碑清理、完整交互和角色限制。
6. **M6 验证与交付**：离线故障注入、真实 R2 主/恢复设备联测、原生桌面和三平台打包。主设备人工接管的可操作步骤及风险说明一同验收；图形化接管向导可后续建设。

每个阶段须保留可提交、可回归的垂直切片，不要求一次性实现完整多设备架构。避免顺带改动下载引擎、图集、MCP、素材工作台或设计系统。

## 11. 验收场景与发布门槛

| 场景 | 可观察验收结果 |
| --- | --- |
| 原数据库升级 | 完成任务数、可播放路径、历史和原文案不丢失；反复启动无重复资产 |
| 初次创建备份空间 | `library.json` 存在且可回读；再次创建不覆盖原库；只读设备无法执行写操作 |
| 下载完成自动备份 | 本地可立即播放，后台持久入队；视频、可用封面和文案远端完成后才显示已备份 |
| 文件已提交、入队前崩溃 | 重启通过完成记录补录；不重复创建资产、重复上传已存在完整对象 |
| 分片上传中断 | 重启核对 `ListParts` 后续传；源变动或 `NoSuchUpload` 安全重启；无永久悬挂分片任务 |
| 上传成功、元数据未发布时退出 | 云端尚不显示不完整资产；重启核验远端对象后发布一次记录 |
| 新设备只读导入 | 列表与标题先出现；刷新期间视频 `GetObject` 请求数为 0；反复导入无重复 |
| 文案独立恢复 | 只读设备未下载视频也能查看、复制和导出已有转录；摘要不匹配的结果不被复用 |
| 并发请求恢复同一视频 | 仅启动一次下载；进度可观察，取消或退出后可继续；不会覆盖同名文件 |
| 恢复中断、磁盘满、内容被篡改 | 坏文件不提交，原有文件不损坏；重启可重试并得到明确状态 |
| 清理下载历史 | 历史任务消失，本地视频、资产元数据和远端备份仍可用 |
| 释放本机副本 | 只删除本机受管理文件；云端请求中无 `PutObject/DeleteObject` |
| 主设备断网删除 | 本机删除成功但显示远端待删除；联网后条件写墓碑并清理远端对象 |
| 上传/恢复途中删除 | 在途任务停用；墓碑之后同一 `asset_id` 不再发布 active，也不能被自动恢复 |
| 恢复设备遇到墓碑 | 云端列表不再允许恢复；已有本机文件继续保留，绝无远端写请求 |
| 连接错误和配置切换 | 权限/签名/网络/空库区分显示；旧库待处理队列不投递到新库 |
| 读取主设备身份异常 | `writer_device_id` 或 `writer_epoch` 不匹配时，主设备写入立即阻断 |
| 人工更换主设备 | 旧密钥撤销后新主设备可显式接管；旧设备重新上线写入被拒绝；无自动选主 |
| 已有下载/转录回归 | 下载、重试、取消、清理历史、封面缓存、系统播放器、转录功能原测试继续通过 |

**证据分层**：离线单元/集成测试使用模拟 S3；真实 Cloudflare R2 使用专用测试 Bucket 和短期凭据；Windows 原生 Tauri、macOS Intel、macOS Apple Silicon 的启动与安装包验证分别记录。没有条件的项目标记 `NOT_RUN` 或 `UNAVAILABLE`，不得使用模拟结果宣称真实 R2 或安装包验证通过。
