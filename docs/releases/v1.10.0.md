# 映取 v1.10.0

发布日期：2026-11-06。本次更新包含自 v1.9.1 以来的全部功能与修复，重点新增个人云端备份、资料库和内置 Telegram 原视频下载。

## 升级说明

- 从 v1.9.1 升级时，数据库在完整备份后一次升级到本版最终结构；失败整体回滚。保留原下载记录、平台配置、解析缓存、视频文案和本地文件。
- Telegram 下载改用内置 SDK，不再需要安装 tdl。旧 tdl 配置和外部会话保留，但本版不再读取；首次使用内置 Telegram 下载时，请在平台账号设置中扫码登录。
- 已下载的语音模型继续使用。现有下载并发选择保持不变；新设置默认同时下载 3 个，支持调整为 1–5 个。
- 使用过本分支最终开发版 v9 数据库的用户可保留数据归并；更早的中间开发结构不提供自动升级，不能手改版本号绕过校验。普通 v1.9.1 用户不受该限制影响。

## 新增个人云端备份与资料库

- 支持 Cloudflare R2、通用 S3 和 Telegram 私有频道三种备份目标，保存视频原件、封面、文案及必要的来源信息。
- 支持多个独立备份空间，可分别查看、编辑和命名，显式选择默认空间。保存其他空间配置或切换查看 Tab，不会意外切换当前自动备份目标。
- 下载完成后可自动关联默认空间并进入备份队列；启用且连接就绪后，可为符合条件的已完成历史视频补登记备份。支持手动备份、重试、取消、查看备份位置和进度。
- 新增资料库展示本地和当前空间中的资产，保留已有资产与空间的对应关系。多个空间中存在同一视频时，操作只作用于选定空间。
- 视频按需恢复：查看列表、封面和文案不下载整部视频；播放、下载或重新提取文案时才恢复。已有有效本地副本直接复用。
- 支持“释放本机空间”，在确认云端媒体有效且没有未同步内容后移除本机副本，保留云端资料及恢复入口。
- 支持后续标题、作者资料、封面和文案更新；不同字段可合并，同字段冲突可查看并选择保留版本。不会把未提交文案或冲突当作可丢弃缓存。
- 远端删除采用持久任务：先确认云端删除记录，再完成受管文件清理和列表移除。卡片持续显示真实阶段，失败保留记录、错误和重试依据。
- 支持按空间设置过期删除记录清理策略，默认关闭；清理不接管其他设备的任务，也不自动删除其他设备的本机视频。
- 新的 S3/R2 对象按资产放在同一层目录，文件名包含内容摘要；已核实的旧深层对象继续兼容读取，不自动批量迁移或清空远端资料。

## 内置 Telegram 下载与存储

- 使用 Rust grammers SDK 直接解析并下载单条视频消息，支持公开用户名及当前账号有权访问的数字频道链接，也可从分享文本中识别链接。
- 原始 MP4、WebM、MOV、MKV 直接保存，不转码；支持同组消息中的指定单条视频，不自动展开整组相册或加入频道。
- 下载和备份可复用同一账号授权，也可分别选择账号；扫码取消、账号切换、退出及重启保留各用途的正确绑定关系。
- 使用真实频道名称展示作者信息；优先读取消息自定义封面和缩略图，无可用封面时通过本机 FFmpeg 抽帧。缺失尺寸和时长时通过 FFprobe 补齐，封面或可选参数读取失败不影响已成功保存的视频。
- 通过共享连接池和有界分片并行改善上传、下载与恢复；封面、媒体及备份共用账号请求预算，服务端限流期间暂停新请求。
- 网络中断后按账号共用重连探测，避免多个任务重复退避。等待重连的 Telegram 下载释放名额，其他平台仍可继续；恢复后保留原任务身份和用户意图。
- 文件引用过期时只刷新并重试受影响的分片，核对消息、文档身份和长度，避免把变化后的媒体误当作原文件。
- Telegram 备份在私有频道保存视频、原始封面和文案；后续文案与元数据更新沿既有视频记录发布，不必重新上传原视频。
- 删除时复用已验证的频道消息索引、批量处理媒体清理，并按大小分段保存删除归档，降低大量资料删除时的重复读取。

## 下载、播放与界面优化

- 调整为“下载中心、下载任务、知识库、系统设置、关于软件”的导航，备份配置按提供商和空间组织，平台账号与存储设置更容易区分。
- 统一任务卡片与列表中的等待、下载、备份、重连、取消和删除状态；长内容通过 Tooltip 展示，减少状态变化造成的卡片高度跳动。
- 重试立即反馈等待状态，等待期间可以取消。下载与备份进度按实际完成字节更新，速度和剩余时间更稳定。
- 改善任务右键菜单、快捷操作及页面切换响应，修复严格 CSP 下组件与提示样式的问题。
- 优化竖屏、方形及横屏视频的播放器尺寸，改善窗口内展示和播放位置管理。
- 文件名规则编辑和预览遵循当前系统的目录分隔符；保存时继续使用可跨平台的命名规则，减少 Windows 路径显示歧义。
- 在排队和下载中也识别重复提交，保留用户的重复下载确认；重试继续复用原任务身份，不覆盖已存在文件。
- 重启后按原提交顺序恢复已提交但中断的下载，保留预览、任务身份及重复确认；仅解析的预览不会被误启动为下载。

## 稳定性与性能修复

- 修复慢网络下上传、完整媒体校验和未缓存索引读取过早超时的问题，保留控制请求的较短期限和及时取消能力。
- 修复取消或丢弃元数据请求时关闭共享连接、打断无关上传的问题；连接重建复用原应用身份，授权失效与普通网络错误分别处理。
- 修复云端恢复的并发调度、切换空间、取消及异步文案回写问题，避免迟到结果覆盖较新的本地内容或其他空间状态。
- 为操作列表增加轻量状态投影和独立只读连接；为资产反查、单项恢复及历史登记增加索引与失效机制，减少大资料库下的重复扫描和主任务锁占用。
- 增加独立上传捕获与导入回执；真正完成的操作及时回收封面和文案捕获正文，未完成、取消和未知发送结果继续保留恢复与清理证据。
- 修复删除后的跨空间隐藏、重新上传及后续清理时序，防止一个空间的删除误隐藏其他空间仍有效的视频。
- 改善网络中断、代理变更、服务端限流及上传确认后的并发恢复；不把未知的发送结果直接当作成功或盲目重发。
- 更新 DTK 固定切片至 5.1.10，并同步解析引擎、上游补丁和第三方许可说明；改进本地媒体参数读取及可选封面处理。
- 修复无私有应用配置时的离线测试依赖、Rust 1.99 的弃用 API 检查，以及慢速 CI 调度下的文案进度测试不稳定问题。

## 使用范围与安装包

- 云端备份面向个人单写使用，同一时间自动同步一个默认空间；不承诺多设备同时上传同一资产或跨重启断点续传。中断的未完成文件会按相应任务流程从头重建并校验。
- 云端数据存入用户自行配置的存储或 Telegram 频道，映取不提供托管云服务。S3/R2 需要用户自己的目标和凭据；Telegram 需要账号对所选频道具备相应权限。
- Windows x64：`Yingqu_1.10.0_x64-setup.exe`。
- macOS Intel：`Yingqu_1.10.0_x64.dmg`。
- macOS Apple Silicon：`Yingqu_1.10.0_aarch64.dmg`。
- macOS 最低版本为 13.3，使用 ad-hoc 签名；Windows 安装包未配置代码签名。

发布前的 Windows x64、macOS Intel 和 macOS ARM64 CI 均已通过。构建与离线测试不替代所有真实平台、网络故障及安装环境的人工验收。
