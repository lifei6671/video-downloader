# 文案与制作手法拆解（WB-306）

知识库笔记新增“文案拆解”和“制作手法拆解”，沿用已有笔记、原文引用、片段及关键帧，不建立第二套学习资料库。Windows 验证见[第二十四批](workbench-knowledge-base-validation.md#第二十四批wb-306-结构化文案和制作手法拆解)；Apple Silicon 原生表单、来源 / 引用、三窗口、重启及两种备份恢复验收见[第 32 批记录](workbench-knowledge-base-validation.md#第-32-批macos-结构化拆解原生验收)；Intel 无可用机器，保持 UNAVAILABLE。

## 模板和引用

文案拆解提供开头、观点、论据、转折、结尾和可借鉴点六字段。至少填写一项，空项记录为“未记录”，不生成猜测内容。从已保存文案选中文字创建笔记后，可选择文案拆解，保留原 document ID 与精确原句；打开引用可核对不可变版本、全文及来源。已有普通“文案学习 / 制作手法”笔记仍是自由文本，不自动转换或重写。

制作手法拆解保存 1～64 项观察，每项包含：画面 / 字幕 / 转场 / 声音维度，观察依据，观察正文，已收藏片段，以及可选的关键帧。片段保留 file ID、标题、原起止毫秒快照；关键帧保留 ID 和实际显示毫秒，实际范围匹配用原始 PTS / timebase 判断，避免四舍五入到片段终点时误拒有效图片。

新引用必须找到本资产的片段 / 指定关键帧，图片与片段必须属于同一文件、同一原始 Source 且画面落在范围内。正文引用复用既有文案校验。媒体缺失不删除笔记或图片，已有资源仍可引用；播放操作按当前文件状态禁用。片段 / 图片被删除后，旧笔记保留原快照，可继续修订文字，不把旧引用绑定到新视频或图片；不能新增指向已删除资源的引用。资源读取尚未成功时显示未读取，不冒充已删除。

引用片段可用已有播放器按范围播放，自动选择其文件版本；关键帧按 ID 单独读取和预览，关闭 / 离开释放 Blob URL。正文修改、引用、失败重试和离开保护沿用原笔记界面。选择模板后类型固定；已有未保存自由文本转模板时保留到首个字段，不丢弃输入或引用。

## 观察依据与内容来源

观察依据由记录者声明，默认“待核验”，可选“观看视频”“聆听声音”“仅看关键帧”。仅看关键帧不能用于声音观察；选择静图依据始终显示“未核验连续运动”，不把截图当作已看完整转场。该字段记录依据，不代表程序自动证明已经观看或聆听。

新拆解默认人工来源。手动记录 AI 结果须显式选择“AI 结果（手动录入）”并填写模型名称；本轮没有调用模型或自动生成分析。origin / model_name 创建后不可修改；人工编辑 AI 拆解时保留 AI 创建来源，服务端设置 human_revised，界面明确显示“已人工修订，保留 AI 创建来源”。旧普通笔记沿原创建来源展示，不追认其最后编辑者。

已保存笔记尚未读取时，来源显示读取中；读取失败显示未知并可重读，不能默认标作人工。修订冲突保留本地字段、来源、模型和引用的 JSON 副本供复制，显式重读后再决定如何处理；提交成功但回读失败不重复创建记录。

## 持久化、命令与恢复

schema **v7** 新增 `note_analyses(note_id,data)`，外键关联原 `asset_notes`，JSON 保存结构化内容和 human_revised。两个表在同一事务保存；修订号 CAS 失败或任一写入失败整次回滚。原笔记类型、ID、来源、引用、检索、工作台和摘要均继续使用既有服务。

新 kind 为 `copywriting_analysis` / `technique_analysis`。完整 Note 增加可选 analysis，旧笔记为空；body 由 Rust 根据结构生成，是全文检索、旧 MCP 读取和纯文本导出的投影，不开放第二份独立正文编辑。原 edit_library_note 修改结构化笔记会明确要求使用拆解表单，避免结构和正文分离；旧自由文本笔记不受影响。

新增 `create_library_analysis(assetId,input)` 和 `edit_library_analysis(assetId,noteId,content,expectedRevision)`，成功仍发 notes 变更事件。input 包含 content、origin、model_name、citations；content 为六字段 copywriting 或 observations 数组 technique。编辑只接收内容和修订号，不接收创建来源、模型或 human_revised。每个文本字段上限 64 KiB，AI 模型名上限 200 字节；界面采用更保守的输入长度限制。

WB-306 首次引入逻辑包 v5；当前 WB-310 writer **v9**，reader **v1～v9**，增加[选题与草稿](ideas-and-drafts.md)，保留[研究专题](research-topics.md)及[比较笔记](video-comparison.md)。Note.analysis 随包保留，旧包不能混入结构化分析；恢复校验 kind / 正文投影 / 创建来源，以及已有片段 / 图片的资产、文件、范围和 Source 关系，非法包在发布目录前失败。已删除引用允许保留为不可用快照；不在分析元数据中新增源绝对路径。排除视频时仍保留文案、结构化笔记和已有 PNG，二次备份 / 恢复关系保持一致。schema v1～v6 升级前保留一致性备份，失败回滚后可重试。

JSON / Markdown 导出保留结构及创建来源、人工修订元信息，TXT 沿旧契约导出正文投影。P1B MCP 继续通过原 read_note / list_notes 读取正文、创建来源、修订和文案引用，保留 Unicode 切片及路径读取边界；不新增结构化媒体字段、工具或写入口，后续受控写入和多模态读取仍由 WB-310 / WB-312 负责。engine **0.17.0** / JSONL **v3** 不变。
