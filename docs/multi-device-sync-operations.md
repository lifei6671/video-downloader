# 云端备份使用与维护

当前实现入口：系统设置 → 远端备份。架构契约见 [方案](r2-multi-device-sync-plan.md)，本轮执行和环境证据见 [验证记录](r2-sync-validation.md)。

## 当前上传规则

当前以个人单写备份为范围，不再承诺多设备同时上传或上传断点续传。视频、封面和文案的新对象统一在`<Prefix>media/<asset_id>/`一层资产目录内：

```text
media/<asset_id>/video-<SHA256>.mp4
media/<asset_id>/cover-<SHA256>.png
media/<asset_id>/transcript-<SHA256>.json
```

文件名保留内容SHA256，防止文案或封面提交失败时覆盖上一份仍被记录引用的内容；设备ID和上传操作ID不再进入对象键。删除后重新上传时，只在文件名增加`r<删除修订>-`，例如`video-r2-<SHA256>.mp4`，后续封面和文案沿用这一修订，仍在同一个资产目录。此标识用于本机旧删除任务清理，不增加目录层级。

100MiB以上文件继续使用流式分片传输，每次重试先清理该目标的未完成会话，再从第1片重新上传，不读取、接管或跳过旧分片。持久化的操作/会话身份只用于取消和残留清理，S3Provider的`resumable_upload=false`；整个对象已成功提交且SHA256/长度一致时可以直接确认。多设备同时上传同一资产不属于当前支持范围，不增加设备选主或远端锁。

新写入使用上述浅层对象布局；已核实的历史深层对象可兼容读取，保持只读保护，不自动清理或 Abort。远端既有对象不会自动迁移或清空，实际兼容范围见[旧云库兼容与恢复](backup-cloud-compatibility-recovery.md)；本地 SQLite 的受控迁移另见[迁移说明](backup-schema-migration.md)。

## 下载完成到开始上传

下载过程中的任务进度统一最多每秒推送一次，百分比、速度和剩余时间随同更新；进入合并以及完成、失败、取消等状态立即更新。条形和圆形下载进度条在两次真实更新之间使用一秒过渡，不推算或提前报告完成；系统开启减少动态效果时关闭过渡。

视频完成下载后先校验媒体、提交最终文件并在同一数据库事务内关联资产和当前备份空间，然后唤醒后台队列。队列确认自动备份已启用、当前空间就绪后排队领取操作；前序上传、删除优先任务、空间重连或限流都可能造成等待。正常完成会主动唤醒，不以固定轮询间隔作为必经延迟。

领取后先对源文件计算完整 SHA-256，记录本轮资产、封面及已有转录的快照。Telegram 提供商再恢复或复用登录、核对账号和频道权限、获取账号文件限制，并读取或更新本地消息映射对应的云端索引投影，以确认当前资产及删除代次。视频属性缺失时补读元数据，已有封面转换为缩略图；最后进行上传事务日志核对、源文件完整性校验及容器元数据检查，再发送视频分片。上述队列等待、网络往返和完整文件校验都会使“下载完成”与首个上传分片之间存在间隔；没有固定秒数承诺。

原视频上传、服务器确认、源文件复验完成后，继续处理封面、已有文案和索引发布。自动备份不等待新文案转录完成，后续产生的文案另行同步。媒体回执和未知发布结果仍沿原日志对账；本次刷新频率调整不减少完整性校验或改变备份协议。

## 连接与空间切换

修改 Telegram 网络代理会回收旧连接，保留账号授权。正在传输的备份和恢复使用原操作 ID 静默重试，不消耗普通失败重试次数；上传保留媒体回执与发布日志，先对账未知结果再继续。Telegram 链接下载在同一任务内重建连接和任务暂存文件。自动重试不弹 Toast，重新领取队列任务时清除旧错误；停止自动重试、需要手动处理的失败才通知。用户取消、退出账号或切换账号仍沿原取消和身份校验流程处理。

Cloudflare R2 使用 S3 预设，Region 为 `auto`；通用 S3 配置 HTTPS Endpoint、Region、Bucket、Prefix 和路径样式。凭据保存在系统凭据库，SQLite 只存凭据引用。通用 S3 可使用含点 Bucket；HTTPS 虚拟主机证书是否兼容仍由实际连接验证，不关闭 TLS 校验。

“测试连接”使用当前草稿，在随机 `probes/<operation_id>/` 内验证读取、列举、竞争条件创建/更新拒绝、Range、分片及清理，不创建资产或改写库元数据。“保存配置”同样验证能力后创建或连接备份库，增加空间 Tab，但不将其它空间设为默认。缺少原子条件写入则拒绝多设备写入，不降级为覆盖。探针清理失败由本机持久日志继续处理，临时凭据保留到清理完成。

备份空间按提供商和存储目标独立保存。顶部 Tab 只用于查看、编辑，来回查看保留本次未保存草稿；默认空间有“默认”标记。标题行右侧启用按钮独立控制自动备份，停用时保留默认空间与待办；未选默认空间时也可先启用。已默认时隐藏“设为默认”，新建时隐藏“删除配置”。“设为默认”仅启用时可用，位于“保存配置”前，必须先保存当前目标和修改才能切换。同一时间只自动同步一个空间，实际切换原子暂停原队列，保留凭据、原操作 ID、续传状态、基线、冲突和墓碑。回切先校验库身份，再恢复原队列；未完成媒体从头上传。已关联任一空间的视频保留原归属，不随默认空间切换重复上传；未关联任何空间的已完成历史视频，在默认空间启用且连接就绪后补登记并自动排队。取消、删除、隐藏及既有操作证据不会被补登记覆盖。图集、失败任务和源文件缺失不自动备份。编辑目标字段会清空显示的旧凭据并进入新空间草稿。

设置页保存使用 `save_backup_settings.config.activate=false`：保存非当前空间保持禁用，默认空间及其队列不变；保存当前空间仍可更新其配置和启用状态。返回值是被保存的空间。`activate`、建库标志及清理设置由当前界面明确提交，缺失时拒绝请求。

已有空间双击 Tab 标签或聚焦后按 F2 原位改名，Enter 或失焦直接保存，Esc 取消；输入法选字时不提交，失败保留输入并显示错误。下方不再重复显示名称输入框，只有新建空间在表单首项填写名称并随“保存配置”保留；未命名时回退到“R2 / Bucket”或“S3 / Bucket”。名称只存本机 `backup_space_names(space_id,display_name)` 表，由备份 schema v7 初始化或兼容迁移保留；已有名称不重写。纯改名使用 `rename_backup_space`，不访问远端、系统凭据或队列；不会提交其它配置草稿或切换默认空间。配置保存支持可选 `display_name`，未提交名称变更时保留已存名称。名称允许清空以恢复默认标题，长度最多 64 个字符且不含控制字符。

当前按单人单写方式使用，不提供同时上传的设备协作保证。Rust 服务负责后台备份与已有记录发现；任务页面只读取本机状态与进度。前台约30秒、后台空闲约180秒拉取，失败有限退避，本机完成下载/转录会唤醒服务。列表与封面、文案读取不恢复视频，播放、首次/重新转录及显式下载按需恢复。有效本机副本直接使用。

## 冲突与删除

同步采用共同基线与实际字段变化进行三方合并。不同字段合并，同字段不同值保留冲突版本。任务标题旁“冲突 N”可查看、采用版本或保留当前版本；选择仍通过条件提交，确认收敛后才消除对应版本。选择期间出现的新修改继续按普通合并规则保留。本机存在未提交变化时先完成同步，避免选择覆盖本机数据。

“释放本机空间”要求云端媒体仍有效且本机没有未同步内容，保留云端资产。释放后的任务仍可从播放入口恢复。“从当前同步库删除”先持久化意图，保留原任务/卡片，发布并确认墓碑、清理当前空间远端消息及附件，成功后再删除发起设备明确选定的受管文件，最后同一事务提交任务移除、当前空间的删除隐藏及本地清理完成标记；其它空间的有效成员仍可显示并恢复。原卡片显示远端删除、本地删除和移除记录的真实阶段；任一步失败保留原记录和错误，重试从持久阶段继续。Telegram 的事件原字节和原修订先归档到库级记录并回读确认，再删除资产消息及其 `yingqu-event.json` 附件；已删资产可从库级索引重建删除状态。其它设备已有视频保持可播放，不自动删除。

其它设备缺文件时，后台墓碑只隐藏云端失效资产。若保留未提交文案/标题或冲突，显示“本机待处理”，可查看并导出 JSON。导出含空间/资产身份、实际 pending 变化和选择、文案及原始冲突引用，不是界面预览占位文本。实际尝试读取缺失视频时才复核最新墓碑；本机曾实际上传并确认活动记录的设备可以清理过期同步投影和可再生缓存，资产、未提交内容、冲突、最小墓碑和来源证明继续保留。404、网络异常和本机文件缺失均不是删除依据。

远端清理包含本空间该资产的旧对象及遗留分片；首轮成功后仍按既有30秒、120秒间隔完成后台复查。重启只恢复尚未完成的操作及其重试期限，不重新排队已完成删除。新删除和尚未完成本机清理的删除优先于上传及后台复查；复查不抢在用户新操作前。其它设备不接管发起者删除任务，不清理其它设备本机文件。未开启清理时，墓碑长期保留。普通过期队列仍不覆盖删除状态；用户可在保留有效本机副本的设备上点击“重新上传”，按新的操作重新发布视频、封面和文案，清除该空间的当前删除状态，不丢弃未同步内容。已发布的活动记录优先于历史删除索引，旧删除任务后续复查不会重新删除已恢复的活动记录。 重新上传文件仍位于`media/<asset>/`，文件名为`<kind>-r<删除修订>-<SHA256>.<ext>`；后续封面和转录沿用当前视频的同一修订标识；发布时校验引用归属，拒绝跨越再次删除后的旧文件。旧清理只处理更早修订的文件和会话，不触碰当前重新上传。已经发布墓碑的复查阶段不再重复发布删除；显式新删除重置复查次数。发布前若删除修订已经改变，则保留本机数据并要求重新上传，不发布指向过期清理范围的文件。所有规则只复用单资产现有修订，不引入设备期限、上传次数限制或全局锁。

重新上传将未解决的本机冲突继续发布并保留导出入口；收到墓碑时将原冲突列为尚未确认发布的本机数据，后台发现其它设备的活动记录不清除这些版本；它们跨重启和显式重试保留，确认发布后才移出待处理列表。另一设备先完成重新上传时，仍合并本机保留的冲突。普通上传跨再次删除后因对象路径过期失败时，显式重试创建新操作，原会话清理证据保留。采用仍存在的封面或转录冲突时，先保存本机内容，再上传到当前修订路径。引用的旧冲突文件即使已经清理，也保留完整引用，详情明确不可采用并可导出，不静默删除冲突记录。

### 自动清理已删除记录

每个空间可在表单启用“自动清理已删除记录”，默认关闭；保留天数默认30，范围1～3650，仅随“新建配置”或“保存配置”写入本机，不随Tab查看或默认空间切换提交草稿。设置按空间隔离，其它设备未启用清理也能读取已经合并的删除索引。

Rust现有后台维护循环仅处理当前启用且就绪的空间，正常每小时检查，失败保存原因并在5分钟后重试；软件退出或停用该空间时暂停，不设置R2 Bucket生命周期规则。只处理本机后台同步已确认的墓碑，不扫描或按时间删除活动视频记录。每次最多确认128项合并，余下留待下一轮。历史删除记录若无可靠时间，首次检查时条件写入起始时间，之后不重置；新删除记录直接记录实际`deleted_at`。

过期`records/<asset_id>.json`先合并到同库`deletions/<UUID前两位>.json`，按条件写有限重试，确认索引持久化后才按原ETag条件删除独立记录。索引只保留资产ID、修订号、删除时间和操作/设备身份，不存视频、封面或文案正文；索引失败、格式不符、库身份不符或原记录已改变时不删除记录。`library.json.deletion_indexes`仅用于宣布索引存在，避免没有索引的空间额外枚举；有索引的空间使用分页及ETag检查，未变化的分片不重复GET。新设备与实际读取从索引识别删除，正常活动记录优先。索引不作为永久禁止再次上传的名单，不引入设备失效、离线期限或全局分布式锁。

S3服务须支持`DeleteObject If-Match`才可安全删除正在合并的精确记录版本，保存开启清理时通过原隔离探针验证错误版本删除被拒绝、正确版本删除成功；停用期间只保存本机策略，首次后台清理前补做相同探针验证。不支持时清理报错，不退回无条件删除。本轮真实服务支持程度须按隔离环境另验，不能由离线fixture冒称通过。

### 对象Content-Type

普通PUT、文件PUT和创建分片上传均设置已验证容器对应的Content-Type：MP4为`video/mp4`，MOV为`video/quicktime`，MKV为`video/matroska`，WebM为`video/webm`，JPEG/PNG/WebP分别为对应`image/*`，库/资产/转录/删除索引JSON为`application/json`。无文件格式的探针仍使用`application/octet-stream`。旧对象的元数据不会自动重写或重新上传。

## 存储连接与初始化

R2/S3 使用唯一的多设备同步协议。界面没有协议选择、升级提示、升级复选框或替换凭据要求；启停不改变默认后端。数字序列化校验字段仅属于内部存储契约，不是可选产品版本。

启停命令只在本机保存期望状态并唤醒现有 Rust 队列。能力验证完成后才能派发传输；停用或换空间取消实际请求，迟到结果不能重新启用。保存及设为默认验证当前库身份，不转换其它格式。测试连接只运行隔离探针；创建库使用当前格式的条件写。网络超时、取消、探针清理及凭据失败继续按现有持久状态恢复。

备份 SQLite schema v7 支持当前规范 v1、v6 和已核验布局的旧 v5 兼容迁移，先完整备份，再同事务转换、检查外键并提交。旧字段与任务原态归档，账号命名空间、媒体回执和消息发送证据不重写；v5 迁移后暂停自动云同步。空间保留 7 列，远端状态保留 4 列。其它版本或不兼容布局明确失败，不自动清空；远端协议不在此转换。详情见[迁移说明](backup-schema-migration.md)。正常下载提交与提交恢复继续登记资产；历史补登记由已启用并就绪的默认后台队列执行，`Core::open` 不等待它。登记、任务关联及待同步状态在同一事务提交，递增任务 revision 后通知界面，标题前显示“待备份”并自动上传。只恢复源文件指纹仍匹配的历史文案，不覆盖已有资产文案；完整 SHA-256 验证通过后才上传文案。图集与本机收藏状态保持原语义。

## 代码入口

| 模块 | 责任 |
| --- | --- |
| `backup/provider.rs` | `BackupProvider`、作用域、不透明状态、媒体引用、能力、`Accepted`/`Converged` 回执 |
| `backup/sync_engine.rs` | 三方合并、修订确认、持久队列及后台发现/传输/维护 |
| `backup/s3_provider.rs` | S3 记录序列化、CAS、浅层媒体目录、分片从头重试及 Range，使用原 ObjectStore/AWS SDK |
| `backup/spaces.rs` / `library.rs` | 空间与凭据、能力门禁及当前库身份校验 |
| `backup/sync_read.rs` / `sync_delete.rs` / `conflicts.rs` | 懒恢复、最小删除及冲突选择/导出 |
| `backup/sync-schema.sql` / `repository.rs` | SQLite 备份 schema v7、独立成员映射、基线、待办、来源证明、墓碑 |

Telegram 由 Rust Core 内的 grammers 实现同级 BackupProvider，以唯一富消息格式保存资产，后提取文案追加到原视频消息。详细契约见 [Telegram 存储技术方案](telegram-storage-plan.md)。

删除配置仅作用于本机：有视频或未结束任务引用时先确认，Rust 在事务内再次检查引用。删除暂停队列、清除默认指向、将凭据加入现有持久清理队列；不删除任何本机视频或远端对象，保留关联、未同步文案、基线、冲突、墓碑和会话证据。配置从列表隐藏，后台不能启用它；重新添加同一目标时复用原空间身份，校验连接并初始化当前格式后重新显示；仍须显式设为默认才能恢复队列，不迁移历史视频。

`backup_sync_preference`、`backup_removed_spaces` 在首次建库时创建。启停、删除配置及显式激活使用当前本机状态，不为旧数据库回填偏好。
