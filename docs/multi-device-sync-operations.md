# 云端备份使用与维护

当前实现入口：系统设置 → 远端备份。架构契约见 [方案](r2-multi-device-sync-plan.md)，本轮执行和环境证据见 [验证记录](r2-sync-validation.md)。

## 当前上传规则

当前以个人单写备份为范围，不再承诺多设备同时上传或上传断点续传。视频、封面和文案的新对象统一在`<Prefix>media/<asset_id>/`一层资产目录内：

```text
media/<asset_id>/video-<SHA256>.mp4
media/<asset_id>/cover-<SHA256>.png
media/<asset_id>/transcript-<SHA256>.json
```

文件名保留内容SHA256，防止文案或封面提交失败时覆盖上一份仍被记录引用的内容；设备ID和上传操作ID不再进入对象键。删除后重新上传时，只在文件名增加`r<删除修订>-`，例如`video-r2-<SHA256>.mp4`，后续封面和文案沿用这一修订，仍在同一个资产目录。此标识用于本机旧删除任务清理，不增加目录层级。

100MiB以上文件继续使用流式分片传输，每次重试先清理该目标的未完成会话，再从第1片重新上传，不读取、接管或跳过旧分片。持久化的操作/会话身份只用于取消和残留清理，S3Provider的`resumable_upload=false`；整个对象已成功提交且SHA256/长度一致时可以直接确认。多设备同时上传同一资产不属于当前支持范围，不增加设备选主或远端锁。

已有深层对象不批量移动或删除，记录中的原对象键继续支持读取、封面/文案获取、按需恢复和显式删除；正在进行的历史上传在重试时清理旧会话并采用新目录从头上传。SQLite和记录格式不变，空间、凭据及历史资产关联保持原样。本节覆盖以下历史多设备设计中的上传路径与续传承诺。

## 连接与空间切换

Cloudflare R2 使用 S3 预设，Region 为 `auto`；通用 S3 配置 HTTPS Endpoint、Region、Bucket、Prefix 和路径样式。凭据保存在系统凭据库，SQLite 只存凭据引用。通用 S3 可使用含点 Bucket；HTTPS 虚拟主机证书是否兼容仍由实际连接验证，不关闭 TLS 校验。

“测试连接”使用当前草稿，在随机 `probes/<operation_id>/` 内验证读取、列举、竞争条件创建/更新拒绝、Range、分片及清理，不创建资产或改写库元数据。“保存配置”同样验证能力后创建或连接备份库，增加空间 Tab，但不将其它空间设为默认。缺少原子条件写入则拒绝多设备写入，不降级为覆盖。探针清理失败由本机持久日志继续处理，临时凭据保留到清理完成。

备份空间按提供商和存储目标独立保存。顶部 Tab 只用于查看、编辑，来回查看保留本次未保存草稿；默认空间有“默认”标记。标题行右侧启用按钮独立控制自动备份，停用时保留默认空间与待办；未选默认空间时也可先启用。已默认时隐藏“设为默认”，新建时隐藏“删除配置”。“设为默认”仅启用时可用，位于“保存配置”前，必须先保存当前目标和修改才能切换。同一时间只自动同步一个空间，实际切换原子暂停原队列，保留凭据、原操作 ID、续传状态、基线、冲突和墓碑。回切先校验库身份，再恢复原队列；未完成媒体从头上传。新空间只接收实际切换之后新完成的视频，不补传历史资产。编辑目标字段会清空显示的旧凭据并进入新空间草稿。

设置页保存使用 `save_backup_settings.config.activate=false`：保存非当前空间保持禁用，默认空间及其队列不变；保存当前空间仍可更新其配置和启用状态。返回值是被保存的空间。旧调用未传该字段时默认为 true，保留原先保存并激活的行为。此变更不需要 SQLite 迁移。

已有空间双击 Tab 标签或聚焦后按 F2 原位改名，Enter 或失焦直接保存，Esc 取消；输入法选字时不提交，失败保留输入并显示错误。下方不再重复显示名称输入框，只有新建空间在表单首项填写名称并随“保存配置”保留；未命名时回退到“R2 / Bucket”或“S3 / Bucket”。名称只存本机新增的 `backup_space_names(space_id,display_name)` 表，启动时用 `CREATE TABLE IF NOT EXISTS` 为旧 v4 数据库补建，版本号仍为 4，旧表和现有身份不变。纯改名使用 `rename_backup_space`，不访问远端、系统凭据或队列；不会提交其它配置草稿或切换默认空间。新配置保存支持可选 `display_name`，旧调用不传时保留已存名称。名称允许清空以恢复默认标题，长度最多 64 个字符且不含控制字符。

当前按单人单写方式使用，不提供同时上传的设备协作保证。Rust 服务负责后台备份与已有记录发现；任务页面只读取本机状态与进度。前台约30秒、后台空闲约180秒拉取，失败有限退避，本机完成下载/转录会唤醒服务。列表与封面、文案读取不恢复视频，播放、首次/重新转录及显式下载按需恢复。有效本机副本直接使用。

## 冲突与删除

同步采用共同基线与实际字段变化进行三方合并。不同字段合并，同字段不同值保留冲突版本。任务标题旁“冲突 N”可查看、采用版本或保留当前版本；选择仍通过条件提交，确认收敛后才消除对应版本。选择期间出现的新修改继续按普通合并规则保留。本机存在未提交变化时先完成同步，避免选择覆盖本机数据。

“释放本机空间”要求云端媒体仍有效且本机没有未同步内容，保留云端资产。释放后的任务仍可从播放入口恢复。“从当前同步库删除”先持久化意图，再清理发起设备明确选定的受管文件、发布墓碑，由发起设备持久任务清理当前空间对象。其它设备已有视频保持可播放，不自动删除。

其它设备缺文件时，后台墓碑只隐藏云端失效资产。若保留未提交文案/标题或冲突，显示“本机待处理”，可查看并导出 JSON。导出含空间/资产身份、实际 pending 变化和选择、文案及原始冲突引用，不是界面预览占位文本。实际尝试读取缺失视频时才复核最新墓碑；本机曾实际上传并确认活动记录的设备可以清理过期同步投影和可再生缓存，资产、未提交内容、冲突、最小墓碑和来源证明继续保留。404、网络异常和本机文件缺失均不是删除依据。

远端清理包含本空间该资产的旧对象及遗留分片；会延后复查并在发起设备重启后继续检查晚到对象。其它设备不接管发起者删除任务，不清理其它设备本机文件。未开启清理时，墓碑长期保留。普通过期队列仍不覆盖删除状态；用户可在保留有效本机副本的设备上点击“重新上传”，按新的操作重新发布视频、封面和文案，清除该空间的当前删除状态，不丢弃未同步内容。已发布的活动记录优先于历史删除索引，旧删除任务后续复查不会重新删除已恢复的活动记录。 重新上传文件仍位于`media/<asset>/`，文件名为`<kind>-r<删除修订>-<SHA256>.<ext>`；后续封面和转录沿用当前视频的同一修订标识；发布时校验引用归属，拒绝跨越再次删除后的旧文件。旧清理只处理更早修订的文件和会话，不触碰当前重新上传。已经发布墓碑的复查阶段不再重复发布删除；显式新删除重置复查次数。发布前若删除修订已经改变，则保留本机数据并要求重新上传，不发布指向过期清理范围的文件。所有规则只复用单资产现有修订，不引入设备期限、上传次数限制或全局锁。

重新上传将未解决的本机冲突继续发布并保留导出入口；收到墓碑时将原冲突列为尚未确认发布的本机数据，后台发现其它设备的活动记录不清除这些版本；它们跨重启和显式重试保留，确认发布后才移出待处理列表。另一设备先完成重新上传时，仍合并本机保留的冲突。普通上传跨再次删除后因对象路径过期失败时，显式重试创建新操作，原会话清理证据保留。采用仍存在的封面或转录冲突时，先保存本机内容，再上传到当前修订路径。引用的旧冲突文件即使已经清理，也保留完整引用，详情明确不可采用并可导出，不静默删除冲突记录。

### 自动清理已删除记录

每个空间可在表单启用“自动清理已删除记录”，默认关闭；保留天数默认30，范围1～3650，仅随“新建配置”或“保存配置”写入本机，不随Tab查看或默认空间切换提交草稿。设置按空间隔离，其它设备未启用清理也能读取已经合并的删除索引。

Rust现有后台维护循环仅处理当前启用且就绪的空间，正常每小时检查，失败保存原因并在5分钟后重试；软件退出或停用该空间时暂停，不设置R2 Bucket生命周期规则。只处理本机后台同步已确认的墓碑，不扫描或按时间删除活动视频记录。每次最多确认128项合并，余下留待下一轮。历史删除记录若无可靠时间，首次检查时条件写入起始时间，之后不重置；新删除记录直接记录实际`deleted_at`。

过期`records/<asset_id>.json`先合并到同库`deletions/<UUID前两位>.json`，按条件写有限重试，确认索引持久化后才按原ETag条件删除独立记录。索引只保留资产ID、修订号、删除时间和操作/设备身份，不存视频、封面或文案正文；索引失败、格式不符、库身份不符或原记录已改变时不删除记录。`library.json.deletion_indexes`仅用于宣布索引存在，避免没有索引的空间额外枚举；有索引的空间使用分页及ETag检查，未变化的分片不重复GET。新设备与实际读取从索引识别删除，正常活动记录优先。索引不作为永久禁止再次上传的名单，不引入设备失效、离线期限或全局分布式锁。

S3服务须支持`DeleteObject If-Match`才可安全删除正在合并的精确记录版本，保存开启清理时通过原隔离探针验证错误版本删除被拒绝、正确版本删除成功；停用期间只保存本机策略，首次后台清理前补做相同探针验证。不支持时清理报错，不退回无条件删除。本轮真实服务支持程度须按隔离环境另验，不能由离线fixture冒称通过。

### 对象Content-Type

普通PUT、文件PUT和创建分片上传均设置已验证容器对应的Content-Type：MP4为`video/mp4`，MOV为`video/quicktime`，MKV为`video/matroska`，WebM为`video/webm`，JPEG/PNG/WebP分别为对应`image/*`，库/资产/转录/删除索引JSON为`application/json`。无文件格式的探针仍使用`application/octet-stream`。旧对象的元数据不会自动重写或重新上传。

## 存储连接与初始化

R2/S3 使用唯一的多设备同步协议。界面没有协议选择、升级提示、升级复选框或替换凭据要求；启停不改变默认后端。数字序列化校验字段仅属于内部存储契约，不是可选产品版本。

启停命令只在本机事务保存期望状态并唤醒现有 Rust 同步队列，不等待网络或配置锁；未连接的空间保持实际禁用，能力验证完成才恢复队列。后台使用已保存凭据校验服务能力和库身份；保存和设为默认沿用同一连接流程，必要时用条件写初始化本次实现产生的开发数据。保持空间、库、资产及对象键不变，不读取或重新上传视频；遇到中断从对象内持久标记继续。能力不满足时明确失败，不能把标记直接改成就绪后跳过实际校验。测试连接只运行隔离探针，不改写库元数据。能力探针总时限 30 秒，元数据响应体读取时限 30 秒，后台连接总时限 120 秒；超时取消请求并持久保留错误、自己的探针清理记录和原始凭据，按现有队列唤醒/60 秒退避重试。停用或更换默认空间取消正在连接的请求，最终事务重新读取期望状态，不能在停用后重新启用。启用期间新完成的下载先加入当前空间，验证就绪后再上传，不补传历史资产。设置页在连接期间每秒、启用清理时每5秒读取本机摘要，保留表单草稿；失败显示原因并可重新连接。启动时只对持久启用的当前空间恢复工作。

初始化保留本机视频、未同步标题/文案、冲突、墓碑及现有队列的私有会话。结果未知的开发期操作保持待复核，不静默重放，也不将 404 当作删除。本机 SQLite 结构调整与远端连接初始化是独立步骤。

## 代码入口

| 模块 | 责任 |
| --- | --- |
| `backup/provider.rs` | `BackupProvider`、作用域、不透明状态、媒体引用、能力、`Accepted`/`Converged` 回执 |
| `backup/sync_engine.rs` | 三方合并、修订确认、持久队列及后台发现/传输/维护 |
| `backup/s3_provider.rs` | S3 记录序列化、CAS、浅层媒体目录、分片从头重试及 Range，使用原 ObjectStore/AWS SDK |
| `backup/spaces.rs` / `library.rs` | 空间与凭据、能力门禁、连接初始化及对账 |
| `backup/sync_read.rs` / `sync_delete.rs` / `conflicts.rs` | 懒恢复、最小删除及冲突选择/导出 |
| `backup/sync-schema.sql` / `repository.rs` | SQLite v4、独立成员映射、基线、待办、来源证明、墓碑 |

未来 Telegram 适配器应实现同级 `BackupProvider`，使用 `TelegramMessage` 引用、自己的凭据与索引事件重放，通过 `Accepted`→重放确认→`Converged` 表达收敛。不能借用 S3 对象键/ETag，也不复用平台下载的 `tdl_bridge` 作为备份服务。目前提供商枚举及协议保留该类型，UI 禁用，后端直接调用返回 `BACKUP_PROVIDER_NOT_IMPLEMENTED`。

## 验证命令

```powershell
cargo test --locked --manifest-path src-tauri/Cargo.toml -- --test-threads=1
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --features desktop --all-targets -- -D warnings
npm run build
git diff --check
```

浏览器使用已安装 Playwright CLI、独立会话和本地 Vite 页面：`tests/s3-backup-browser.mjs`、`tests/multi-device-sync-browser.mjs`。三视口是1440×900、1280×800、1024×680，截图在忽略目录 `output/playwright/`。模拟 IPC 不替代原生 Tauri 验收。

在线用例默认 ignored，只有明确授权隔离 Bucket/Prefix 后才运行：

```powershell
cargo test --locked --manifest-path src-tauri/Cargo.toml p6_real_r2_v2_ -- --ignored --nocapture --test-threads=1
cargo test --locked --manifest-path src-tauri/Cargo.toml p6_real_generic_s3_v2_two_devices -- --ignored --nocapture --test-threads=1
```

R2 使用仓库根目录私有 `s3-r2-test.local.json` 的写凭据；两台设备使用平等写权限，不使用只读凭据。通用 S3 使用独立忽略文件 `s3-sync-test.local.json`，字段为 `schema_version:1`、`environment:"dedicated-test"`、`endpoint`、`bucket`、非空尾斜杠 `prefix`、`region`、`path_style`、`credentials:{access_key_id,secret_access_key}`。两者都会在授权前缀下创建新的 UUID run，记录脱敏清理日志 `.local/sync-v2-test-runs.jsonl`，结束清空本轮对象与分片。不要填入生产库配置。

删除配置仅作用于本机：有视频或未结束任务引用时先确认，Rust 在事务内再次检查引用。删除暂停队列、清除默认指向、将凭据加入现有持久清理队列；不删除任何本机视频或远端对象，保留关联、未同步文案、基线、冲突、墓碑和会话证据。配置从列表隐藏，后台不能启用它；重新添加同一目标时复用原空间身份，校验连接并初始化当前格式后重新显示；仍须显式设为默认才能恢复队列，不迁移历史视频。

本机 v4 数据库启动时幂等补建 `backup_sync_preference(id,enabled)` 和 `backup_removed_spaces(space_id)`，未写入偏好时继承旧默认空间的启用状态。无表结构改写或远端迁移。新增 IPC 为 `get_backup_sync_enabled`、`set_backup_sync_enabled`、`get_backup_space_usage`、`delete_backup_space`；删除确认参数必须显式传入。
