# Telegram 原始视频下载

Telegram 下载使用现有 Rust `grammers-client` 0.11.0，不需要外部 tdl、伪终端或本地 HTTP 服务。存储备份与平台下载默认复用应用内的 Telegram 账号，也可按用途选择其他账号；各下载任务独立持有 SDK sender pool。

## 使用

在“系统设置 → 平台账号 → Telegram”扫码登录，按需输入两步验证密码。已登录下载或备份账号时，另一处默认复用。点击“切换其他账号”只为当前用途扫码，不改变另一处的账号。两处选择分别保存在本机，下载/备份请求会恢复各自保存的 SDK 授权。仅有旧 tdl 登录时需要重新扫码，不导入、覆盖或删除旧工具会话。

切换只有在新账号授权成功且本机选择保存成功后生效，取消、授权失败或保存失败继续使用原账号。切换成功及退出账号会取消当前用途的旧任务/请求；下载队列中的 Telegram 任务先于正在下载的任务取消，其他平台队列及另一用途不受影响。共用账号时退出当前用途只解除这一处的使用，不撤销另一处仍在使用的授权。已有备份空间的账号/频道绑定不随登录账号改变；不匹配时显示绑定账号并禁用重新连接，需要切回原账号或新建空间。

本机 `telegram_account_bindings` 仅记录 `download` / `backup` 的会话引用 UUID，不保存授权密钥，也不参与远端备份。没有选择记录时，两处都使用原 `backup_device.device_id/session-v1` 会话，不迁移或复制旧密钥。扫码替换期间新任务继续使用尚未切换的原账号；新账号的 `ready` 在选择保存前对界面表现为连接中。

账号页只在实际 `ready` 且存在账号时显示退出操作；操作 ID 仅标识请求生命周期，不表示已登录。当前页面每秒读取本机授权状态，扫码/连接期间每 250ms 读取，不新增 Telegram 网络探测。后台授权失效会移除账号显示并清除可选频道；网络错误、频道权限错误和两步验证密码错误保留各自可继续的状态。扫码失败的“重新扫码”保留是否切换其他账号的选择，自动读取频道不清除扫码失败提示。已成功登录后的迟到取消及旧恢复结果不能清掉或覆盖新账号。

服务端确认旧授权失效后，普通扫码会使用新的待授权会话，仅在成功后替换当前用途，不覆盖另一处保留的会话记录。服务端退出成功但本机凭据清理失败时显示未登录并保留错误及清理记录，可再次恢复/清理；不继续显示已撤销的账号。下载与备份收到明确认证失效时都会更新共用授权状态。

支持 `https://t.me/<username>/<message>` 和 `https://t.me/c/<channel>/<message>` 的单条视频消息，兼容 telegram.me 和分享文本。公开用户名直接解析；数字频道从当前账号可访问的会话取得身份。不自动加入频道，不要求备份库、频道管理或发布权限。同组中的单条视频消息可独立下载；不展开整组消息或图片相册，不支持话题、讨论区及带 query/fragment 的链接。

## 下载契约

- 使用现有全局 1–3 下载槽位及 FIFO 队列；主动解析不占下载槽位。下载期间可以解析其他频道，取消一项只停止自己的请求和 sender pool。切换或退出下载账号会取消该用途的任务并等待回收；退出备份账号不撤销下载授权，应用关闭停止两处会话及所有下载连接。
- 解析和下载分别读取原消息，核对数字频道、消息 ID、文档 ID（新预览）、文件大小、类型及清理后的文件名。原始 MP4、WebM、MOV、MKV 字节直接落盘，不转码。账号需要有实际读取权限。
- 消息检查限时 60 秒；文件分块读取使用 60 秒闲置期限，整个操作上限 6 小时。网络、认证、限流及权限错误明确传播。只有 `FILE_REFERENCE_EXPIRED` 才重新读取原消息，从零重启一次；不提供跨重启断点续传。
- 每块写入及 flush 完成后统计进度，沿用约 250ms 的字节、速度和 ETA 更新。完整长度、容器文件头和落盘同步通过后，交给现有不覆盖提交、SQLite 完成记录与备份入队逻辑。
- 沿用下载后的本地 FFmpeg 抽帧与 SQLite 封面缓存；抽帧失败不改变视频下载结果。失败/取消清理当前任务暂存，不清理用户文件。
- 旧任务中的 `tdl` resolver 仅作为历史快照读取兼容；重试使用 grammers。旧 SQLite 设置表和外部 tdl 会话保留且不再读取或使用。旧预览不用于跳过实时身份检查，已有历史封面继续可读。

## 显式在线验收

`src-tauri/tests/telegram_download_live.rs` 默认忽略，不会在普通测试中读取真实会话。只有明确授权两条消息后，使用本机忽略目录中的 JSON 配置运行：

```powershell
$env:YINGQU_TELEGRAM_DOWNLOAD_TEST_CONFIG = (Resolve-Path .local/telegram-download-online/config.json).Path
cargo test --locked --manifest-path src-tauri/Cargo.toml --test telegram_download_live -- --ignored --nocapture
```

配置字段为 `session_device_id`（现有 SDK QA 会话引用 UUID）、`work_directory`（绝对路径）、`links`（两条获准读取的消息链接）和 `engine`（已有引擎文件路径）。不把配置、账号标识、真实链接或授权材料加入版本控制，也不从普通用户数据库复制账号或任务数据。测试每次创建独立 UUID 目录，通过正常 SDK 恢复授权，只读取远端消息；取消/重试、完成提交和恢复检查仅操作该目录的 QA 数据库及媒体。保留现有授权和媒体，不上传、不删除远端消息、不创建备份空间。
