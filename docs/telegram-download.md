# Telegram 原始视频下载

Telegram 下载使用现有 Rust `grammers-client` 0.11.0，不需要外部 tdl、伪终端或本地 HTTP 服务。存储备份与平台下载默认复用应用内的 Telegram 账号，也可按用途选择其他账号；同一授权的下载、解析与备份复用主 SDK sender pool，文件 RPC 使用独立媒体 TCP 槽。

## 使用

平台账号的 Telegram 页提供直连与 SOCKS5 代理设置，支持含用户名和密码的地址。代理由下载和备份的 SDK 连接共同使用，与账号用途绑定分开保存；普通设置仅返回无凭据地址，完整认证地址沿用系统凭据存储。保存后扫码、恢复、频道请求和新下载使用新配置；代理真正变化时停止旧连接并等待回收，任务沿原操作自动重试后使用新配置。删除备份配置或退出任一用途均不清除代理。HTTP 和 MTProxy 不在当前 SDK 的支持范围内。

删除 Telegram 备份配置仅移除本机配置，不退出 Telegram，也不影响平台账号；平台账号退出只解除下载用途，保留远端备份账号及配置。

在“系统设置 → 平台账号 → Telegram”扫码登录，按需输入两步验证密码。已登录下载或备份账号时，另一处默认复用。点击“切换其他账号”只为当前用途扫码，不改变另一处的账号。两处选择分别保存在本机，下载/备份请求会恢复各自保存的 SDK 授权。仅有旧 tdl 登录时需要重新扫码，不导入、覆盖或删除旧工具会话。

切换只有在新账号授权成功且本机选择保存成功后生效，取消、授权失败或保存失败继续使用原账号。切换成功及退出账号会取消当前用途的旧任务/请求；下载队列中的 Telegram 任务先于正在下载的任务取消，其他平台队列及另一用途不受影响。共用账号时退出当前用途只解除这一处的使用，不撤销另一处仍在使用的授权。已有备份空间的账号/频道绑定不随登录账号改变；不匹配时显示绑定账号并禁用重新连接，需要切回原账号或新建空间。

本机 `telegram_account_bindings` 仅记录 `download` / `backup` 的会话引用 UUID，不保存授权密钥，也不参与远端备份。没有选择记录时，两处都使用原 `backup_device.device_id/session-v1` 会话，不迁移或复制旧密钥。扫码替换期间新任务继续使用尚未切换的原账号；新账号的 `ready` 在选择保存前对界面表现为连接中。

账号页只在实际 `ready` 且存在账号时显示退出操作；操作 ID 仅标识请求生命周期，不表示已登录。当前页面每秒读取本机授权状态，扫码/连接期间每 250ms 读取，不新增 Telegram 网络探测。后台授权失效会移除账号显示并清除可选频道；网络错误、频道权限错误和两步验证密码错误保留各自可继续的状态。扫码失败的“重新扫码”保留是否切换其他账号的选择，自动读取频道不清除扫码失败提示。已成功登录后的迟到取消及旧恢复结果不能清掉或覆盖新账号。

服务端确认旧授权失效后，普通扫码会使用新的待授权会话，仅在成功后替换当前用途，不覆盖另一处保留的会话记录。服务端退出成功但本机凭据清理失败时显示未登录并保留错误及清理记录，可再次恢复/清理；不继续显示已撤销的账号。下载与备份收到明确认证失效时都会更新共用授权状态。

支持 `https://t.me/<username>/<message>` 和 `https://t.me/c/<channel>/<message>` 的单条视频消息，兼容 telegram.me 和分享文本。公开用户名直接解析；数字频道从当前账号可访问的会话取得身份。不自动加入频道，不要求备份库、频道管理或发布权限。同组中的单条视频消息可独立下载；不展开整组消息或图片相册，不支持话题、讨论区及带 query/fragment 的链接。

## 下载契约

Telegram 解析、平台下载、备份队列及恢复下载遇到 `TELEGRAM_CONNECTION_ERROR`、`TELEGRAM_TIMEOUT` 或 `TELEGRAM_NOT_CONNECTED`，以及备份流断开、传输超时时，按账号共用连接探测，间隔 1、2、4、8、15 秒后持续以 15 秒重试，直到实际 `get_me` 成功且账号仍匹配。等待不计入业务失败次数；新 Telegram 任务先等待连接，等待中的 Telegram 任务释放下载名额，其他平台仍可执行；原任务恢复连接并重新取得名额后自动继续，取消、退出、账号切换及备份停用/空间切换保留停止语义。平台下载失败尝试的临时文件会清理，恢复后从头重建并校验完整文件，不提供跨重启断点续传。启动时自动恢复仍为网络错误的历史 Telegram 任务，保留任务 ID 和原解析/下载意图；当前备份空间内仅网络错误阻塞的上传、删除及取消后的清理也自动恢复，保留操作阶段、发送身份和回执。权限、授权、限流、媒体身份变化、本地 I/O 和校验错误继续按原规则处理，不自动重放未知发送结果。

备份准备中的只读账号、配置、频道和消息读取，以及文件引用刷新仍保留最多 3 次的短重试，间隔 200 / 400 ms；耗尽后的网络错误由上述账号重连机制处理。SDK 继续使用 `NoRetries`，发送、发布和删除不经过只读重试入口，而由原操作 journal 对账后继续。旧独立附件的恢复和引用刷新按已保存的消息/文档身份读取；富消息、发布确认、校验及删除保持原严格索引验证。

- 频道展示使用 SDK 从同一频道资料取得的真实标题，写入 `author_profile.nickname` 和兼容的 `author`；数字频道 ID 仍用于媒体身份和本地频道搜索，在任务详情可查。频道改名只更新展示元数据，不构成文件引用刷新时的媒体身份变化。下载或重试会补齐本任务的频道名，并在缓存文档身份仍相同时更新缓存；历史文件不重命名。缺少名称的旧记录仅显示已知名称、公开用户名或“Telegram 频道”，不再以数字 ID 代替名称。

- 使用现有全局 1–5 下载槽位及 FIFO 队列；主动解析不占下载槽位。下载期间可以解析其他频道，取消一项只停止自己的请求，不关闭共用池。切换或退出下载账号会取消该用途的任务并等待回收；退出备份账号不撤销下载授权，应用关闭停止两处会话及所有下载连接。
- 解析和下载分别读取原消息，核对数字频道、消息 ID、文档 ID（新预览）、文件大小、类型及清理后的文件名。原始 MP4、WebM、MOV、MKV 字节直接落盘，不转码。账号需要有实际读取权限。
- 消息检查限时 60 秒；文件读取保留 60 秒闲置期限和整个操作 6 小时上限。原视频使用共享分片引擎的 512 KiB 请求和有界并行窗口，默认最多 8 个工作任务，按文件大小减少。1 MiB 响应会触发 grammers-mtproto 0.11 的容器解码上限，因此本版主动降低分片而不扩大底层协议解析限制。单请求 25 秒超时，网络/服务端临时错误最多尝试 4 次并随机退避。账号上传、原视频下载和封面共用 16 个文件请求槽位；服务端限流期限内不发新文件请求。
- 文件引用过期时，在分片层重新读取原消息并核对文档身份、大小、MIME 和属性；只重试未完成分片，最多刷新两次，耗尽明确失败。迁移按目标 DC 路由，禁用 CDN 且拒绝意外重定向，不把 CDN 密文当媒体；不提供跨重启断点续传。
- 分片可乱序完成，单个写入者立即按 offset 写入任务暂存文件，再补发下一片，不共享并发文件游标。每秒更新字节、速度和 ETA，速度按约五秒真实有效字节计算，不再每片 flush；完整长度、容器文件头和最终落盘同步通过后，交给现有不覆盖提交、SQLite 完成记录与备份入队逻辑。实现和测量边界见[传输验证](telegram-transfer-performance-validation.md)。
- 解析及下载优先读取消息自定义 `video_cover`，其次读取文档缩略图；同组候选优先较大图片，缺失、损坏或读取失败时继续回退。图片沿用账号和代理连接，限制大小、解码及读取时间。仅在没有可用远端封面时由 Rust 直接调用本地 FFmpeg 抽帧；封面缓存随任务和解析缓存持久保存，封面失败不改变视频下载结果。失败/取消清理当前任务暂存，不清理用户文件。
- 清晰度与时长读取 Telegram 的 `DocumentAttributeVideo`；缺失时在原视频下载完成后由 Rust 直接调用现有 FFprobe 补齐，并保存任务及解析缓存。启动时顺序补齐已有本机视频的缺失参数，关闭可取消；云端未提供参数且本机没有文件时保持未知，不推测分辨率。
- 旧任务中的 `tdl` resolver 仅作为历史快照读取兼容；重试使用 grammers。旧 SQLite 设置表和外部 tdl 会话保留且不再读取或使用。旧预览不用于跳过实时身份检查，已有历史封面继续可读。

Telegram 的参数读取和抽帧不启动 Python sidecar。工具查找覆盖应用托管目录、PATH 和现有 Windows/macOS 常见安装目录；Windows 隐藏工具窗口，使用 Job Object 回收进程，Unix 使用独立进程组。参数读取、工具验证和抽帧均保留时限、取消及错误传播；可选封面失败不改变视频下载成功。其他平台与转写功能继续使用其既有引擎。

## 显式在线验收

`src-tauri/tests/telegram_download_live.rs` 默认忽略，不会在普通测试中读取真实会话。只有明确授权两条消息后，使用本机忽略目录中的 JSON 配置运行：

```powershell
$env:YINGQU_TELEGRAM_DOWNLOAD_TEST_CONFIG = (Resolve-Path .local/telegram-download-online/config.json).Path
cargo test --locked --manifest-path src-tauri/Cargo.toml --test telegram_download_live -- --ignored --nocapture
```

配置字段为 `session_device_id`（现有 SDK QA 会话引用 UUID）、`work_directory`（绝对路径）、`links`（两条获准读取的消息链接）和 `engine`（已有引擎文件路径）。不把配置、账号标识、真实链接或授权材料加入版本控制，也不从普通用户数据库复制账号或任务数据。测试每次创建独立 UUID 目录，通过正常 SDK 恢复授权，只读取远端消息；取消/重试、完成提交和恢复检查仅操作该目录的 QA 数据库及媒体。保留现有授权和媒体，不上传、不删除远端消息、不创建备份空间。
