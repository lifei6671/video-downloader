# S3/R2 备份运维与接管

## 数据库备份与换机恢复

- 保存 S3/R2 或 Telegram 空间后，可单独开启数据库备份，默认关闭。每次开启时设置并确认 12 至 128 个字符的恢复密码，点弹窗底部「自动生成」会直接保存密码并关闭弹窗，可在设置中复制。密码丢失后无法恢复对应备份。若重新开启时输入了不同的密码，先前的快照仍需要创建它们时的密码。应用使用远端库 ID 和 scrypt 派生 age 加密密钥，本机系统凭据库存放密钥及可复制的自动生成密码。数据库快照（含平台 Cookie）在本机加密后上传。
- 开启数据库自动备份后，从开启时起按所选间隔安排首次上传。各空间可选每 1、3、6 或 24 小时，默认 24 小时。「立即备份」可手动安排。备份排队或执行时可以取消，结束前不能再启动同一空间的备份。上传失败或取消后，下一次自动执行按所选间隔安排，也可手动重新开始。界面显示上传进度、速度、上次成功时间和平均上传速度。Telegram 可复制最近一次成功备份的链接，用于在恢复时直接定位包含加密文件的频道消息。上传确认后保留同设备、同密钥的最近三份，Telegram 清理需要频道删除权限。单份快照上限 4 GiB，同时受 Telegram 账号的上传限额约束。关闭选项后可以继续恢复已有快照。
- S3/R2 换机时先保存原来的 Endpoint、Bucket 和 Prefix，在「恢复数据库」中输入恢复密码并选择快照。Telegram 换机时登录原账号并选中原私有频道，即可直接点「恢复数据库」。粘贴从设置复制的数据库备份链接，或在 Telegram 里对包含 `yingqu-database.age` 的消息使用「复制消息链接」。输入恢复密码后，应用仅查询所选消息。
- 重新打开应用时应用快照，并在同一数据目录保留一份 `*.before-database-restore-*.sqlite` 以便回退。
- 恢复保留快照中的本地历史、设置、文案及云端资产映射，并使用新设备的设备身份、下载目录和当前空间的凭据或频道会话。旧设备的绝对媒体路径和执行中的操作会清除。任务列表来自 SQLite 快照；刷新只核对数据库已有的云端视频。视频仍从原空间按需下载，图集原图等未备份媒体需从原存储取回。恢复后可再次勾选数据库自动备份。

## 凭据与设置

R2 使用 S3 API Endpoint、Bucket、Prefix、Access Key ID 和 Secret Access Key。主设备凭据限定到对应 Bucket 的对象读写，恢复设备凭据限定对象读取。Prefix 是应用操作边界，桶权限由 S3 服务控制。新设备先连接原空间，再从加密快照恢复任务列表。

应用只把凭据引用写入 SQLite，凭据本体在系统凭据存储。设置编辑器默认以掩码回填，可点击眼睛显隐。测试连接使用当前输入，不要求先保存；它验证读取连接及已有库身份，不创建库或验证写权限，保存后才应用配置。关闭已有配置可以离线执行；切换空间会冻结旧空间操作，不能把旧待办转移到新空间执行。重新启用旧空间后按原身份处理其待办。生产库不要使用测试凭据或复用测试前缀。

## 删除与恢复

“从列表移除”只隐藏本机历史，文件、文案与备份保留。“仅释放本机副本”只删除身份核验通过的本机文件。“删除视频及备份”仅供主设备：本机删除失败会阻止远端删除；本机删除成功后即使离线，也保留远端待删除状态。永久墓碑先发布，再清理记录过的精确对象键与分片。失败时修正权限/网络后重试，不手动清空操作表，不删除墓碑。

只读设备刷新遇墓碑，不自动删除其本机副本，但禁止重新从云端恢复。有效本机副本播放不依赖网络；已有文案独立读取。恢复中取消保留可续传暂存，明确释放/删除会清理该资产拥有的暂存；不清扫其他文件。

## 手动主设备接管

先等待旧设备的备份完成，手动生成最后一份数据库快照，再停止旧设备的备份并撤销其写凭据。新设备连接同一存储目标，恢复最后一份快照并验证视频按需下载。确认后为新设备配置写权限，并按需启用新的数据库快照计划。

## 专用 R2 测试

根目录 `s3-r2-test.local.json` 已被 Git 忽略。仅填写已授权专用 Bucket、隔离前缀和两组 S3 凭据，不在聊天或普通日志粘贴密钥。测试在配置前缀下新建随机 run 子前缀，使用临时 SQLite 和生成媒体；清理只针对本次 run 的白名单键，不创建或删除 Bucket。

完整在线测试入口：`cargo test --locked --manifest-path src-tauri/Cargo.toml real_r2 -- --ignored --nocapture --test-threads=1`。包含小文件闭环和100 MiB分片重启续传，各自使用独立随机 run 前缀。只运行小文件可将筛选器改为 `real_r2_m2_dedicated_prefix`。这些测试默认忽略，运行前必须确认专用环境授权仍有效。

分片测试在真实首分片成功后模拟响应丢失，关闭并重开临时数据库，以 ListParts 对账后续传；这是应用重启和响应丢失测试，不是系统掉电测试。读者调用按 ObjectStore 边界计数，日志不包含对象键或凭据。清理包含已证明拥有的精确媒体键下未完成分片，以及本次 run 的白名单对象，并回读确认清空。清理请求本身失败时仍会报告失败；运行标识保存在忽略目录 `.local/r2-test-runs.jsonl`，不得假设远端已清空。真实验证结果见 [阶段验收记录](s3-backup-validation.md)。
