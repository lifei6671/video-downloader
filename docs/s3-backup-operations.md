# S3/R2 备份运维与接管

## 凭据与设置

首版使用 R2 的 S3 API Endpoint、Bucket、Prefix、Access Key ID 和 Secret Access Key。API Token 值不能直接填写到 S3 Secret 字段。主设备凭据限定到对应 Bucket 的对象读写，恢复设备凭据限定对象读取。Prefix 是应用操作边界，不能代替 Bucket 权限。只在系统设置开启备份；新设备先选择恢复设备连接已有库，清单自动导入下载任务，读取视频时才下载。

应用只把凭据引用写入 SQLite，凭据本体在系统凭据存储。设置编辑器默认以掩码回填，可点击眼睛显隐。测试连接使用当前输入，不要求先保存；它验证读取连接及已有库身份，不创建库或验证写权限，保存后才应用配置。关闭已有配置可以离线执行；切换空间会冻结旧空间操作，不能把旧待办转移到新空间执行。重新启用旧空间后按原身份处理其待办。生产库不要使用测试凭据或复用测试前缀。

## 删除与恢复

“从列表移除”只隐藏本机历史，文件、文案与备份保留。“仅释放本机副本”只删除身份核验通过的本机文件。“删除视频及备份”仅供主设备：本机删除失败会阻止远端删除；本机删除成功后即使离线，也保留远端待删除状态。永久墓碑先发布，再清理记录过的精确对象键与分片。失败时修正权限/网络后重试，不手动清空操作表，不删除墓碑。

只读设备刷新遇墓碑，不自动删除其本机副本，但禁止重新从云端恢复。有效本机副本播放不依赖网络；已有文案独立读取。恢复中取消保留可续传暂存，明确释放/删除会清理该资产拥有的暂存；不清扫其他文件。

## 手动主设备接管

首版无接管向导。以下步骤是管理员操作规程，未在真实 R2 环境验证，不承诺仅修改设备 ID 即具有强互斥性。

1. 停止旧主设备及其自动启动，记录当前 library_id、writer_device_id、writer_epoch，以及未完成操作。备份旧设备数据库，避免丢失尚未发布的对象清理清单。
2. 在 R2 撤销旧主设备的写凭据。使用旧凭据对专用探针键确认写入被拒绝，并确认权限变更已生效；若无法验证，停止接管。不得同时保留两个可写凭据的旧进程。
3. 新设备先以只读角色连接同一 Endpoint/Bucket/Prefix，确认库和已发布资产正确。在新设备关闭应用后，从其 SQLite 的 backup_device（id=1）读取稳定 device_id；不要复制旧主设备数据库制造相同 device_id。
4. 使用支持 S3 条件 PutObject 的管理工具读取精确 `<prefix>/library.json` 及其 ETag，保存原 JSON。只修改 writer_device_id 为新设备 ID、writer_epoch 加 1，保持 schema_version、library_id、mode、created_at 不变。使用 `If-Match: <刚读取的 ETag>` 写入同一键。若返回 412，重新调查库状态，不能无条件覆盖。回读并确认新身份。
5. 为新主设备签发限定 Bucket 的新对象读写凭据，在应用设置中切换主设备并保存。先在专用测试环境验证新主设备可以写，旧主设备使用旧凭据重上线仍被拒绝；生产迁移仍需按相同步骤单独验收。
6. 用另一个独立数据目录的只读设备确认清单、文案和按需恢复。旧数据库中的未完成上传/删除不能盲目迁移或清空；根据其精确对象清单和远端墓碑人工核对。新主设备不拥有旧进程内存中的未知对象清单，不能据此自动扫桶清理。

记录每步操作者、时间、Bucket/Prefix、库 ID、旧/新 epoch、ETag 和验证结果，不记录密钥。撤销失败、旧凭据仍可写、身份/ETag 不符时停止写入并处理原因。

## 专用 R2 测试

根目录 `s3-r2-test.local.json` 已被 Git 忽略。仅填写已授权专用 Bucket、隔离前缀和两组 S3 凭据，不在聊天或普通日志粘贴密钥。测试在配置前缀下新建随机 run 子前缀，使用临时 SQLite 和生成媒体；清理只针对本次 run 的白名单键，不创建或删除 Bucket。

完整在线测试入口：`cargo test --locked --manifest-path src-tauri/Cargo.toml real_r2 -- --ignored --nocapture --test-threads=1`。包含小文件闭环和100 MiB分片重启续传，各自使用独立随机 run 前缀。只运行小文件可将筛选器改为 `real_r2_m2_dedicated_prefix`。这些测试默认忽略，运行前必须确认专用环境授权仍有效。

分片测试在真实首分片成功后模拟响应丢失，关闭并重开临时数据库，以 ListParts 对账后续传；这是应用重启和响应丢失测试，不是系统掉电测试。读者调用按 ObjectStore 边界计数，日志不包含对象键或凭据。清理包含已证明拥有的精确媒体键下未完成分片，以及本次 run 的白名单对象，并回读确认清空。清理请求本身失败时仍会报告失败；运行标识保存在忽略目录 `.local/r2-test-runs.jsonl`，不得假设远端已清空。真实验证结果见 [阶段验收记录](s3-backup-validation.md)。
