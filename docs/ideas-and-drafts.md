# 自己的选题与草稿（WB-309）

## 创作与参考

工作台和知识库提供“选题与草稿”入口，工作台展示最近编辑的六项及实际总数。选题列表可新建和打开记录，分别填写选题、自己的观点和草稿；标题必填，允许先保存只有标题的选题。观点最多 64 KiB，草稿最多 16 MiB。工作台只读取标题、修订、字数和参考数量，不带观点、正文或源文件路径。

视频资料“写选题”、片段“用于选题”、研究专题“写选题”创建一份仅预选该参考的新稿。自己的标题 / 观点 / 正文默认留空，不复制原文或研究内容；源页面有未保存编辑时先走既有离开保护。

草稿可关联视频、片段和研究专题。视频 / 片段选择复用既有知识库搜索、分页及来源列表，研究专题选择已有记录。选择只加入当前编辑中的参考列表，和正文一起显式保存；同种资料不能重复加入。移除参考只解除关系，保存前可取消，不删除来源、媒体、笔记或专题成员。

视频打开现有资产详情并提供“返回草稿”，草稿编辑器隐藏且停止报告编辑状态；有未保存内容时可以继续编辑，或保存 / 放弃后打开来源。片段使用原始文件绑定的范围播放器，专题只读展示当前研究内容、成员和修订，可继续打开成员。来源 Dialog 关闭释放播放器并恢复焦点，读取失败可见；参考内容不会自动进入自己的正文。

参考指向现有资料，标题和专题修订随当前记录读取。片段的文件、时间和文案版本仍由原 clip 记录管理；比较笔记的固定来源契约不变。来源归档、文件缺失 / 变化各自显示，重新关联后旧片段复用原领域的 Source 判断。来源记录删除后保留引用身份和最后保存的名称，标“引用缺失”；已有缺失引用不阻止修订自己的文字，不能把新建的未知 ID 当成合法参考，也不按同名资料重新绑定。

## 保存、冲突与读取

正文、观点和完整参考列表使用选题级 revision CAS，在同一事务提交。新加入参考由 Rust 验证种类、资产归属和资料存在性；旧引用仅在种类 / ID / 资产完全一致时可保留缺失状态。任一失败不提交部分正文或引用，失败后保留当前输入。

WB-309 交付时仅支持人工编辑；WB-310 已支持独立授权的 MCP 新建，AI 创建来源和引用只读保留，详见[受控写入](mcp-write-tools.md)。原文、整理稿、研究笔记、专题内容与自己的稿件仍各自存储，保存草稿不改写任何来源。

读取最新稿件不会静默抹掉当前输入。CAS 冲突时保留完整观点、正文和参考列表；明确读取最新后，以 JSON 副本保留当前内容及预期修订，可复制或显式移除。尚有未保存内容或保留副本时，沿用保存 / 放弃 / 继续编辑保护。切换选题或关闭来源会忽略迟到响应，不将其他选题内容填入当前稿件。

提交成功但回读失败时保存返回的 ID 和新修订，明确提示“草稿已保存”，禁止重复写入，按同一 ID 重读。参考读取更新仅刷新当前资料状态和服务端修订提示，不覆盖自己的编辑内容。

## 数据与命令

WB-309 的 schema **v10** 新增以下表；当前 schema v11 为 library_ideas 及 research_topics 增加可空 ai_source_json，详见[受控写入](mcp-write-tools.md)：

| 表 | 字段与边界 |
| --- | --- |
| `library_ideas` | `id,title,viewpoint,body,revision,created_at,updated_at` |
| `idea_references` | `idea_id,kind,asset_id,resource_id,label,asset_title,position,created_at`；主键为 idea / kind / resource，外键只关联选题 |

kind 仅 video / clip / topic。视频要求 resource_id 等于 asset_id；片段须属于声明资产；专题的 asset_id 必须为 null。名称快照最多 512 个 Unicode 标量，仅用于缺失显示，没有源路径或正文副本。参考顺序随完整列表保存，来源删除不级联删除选题引用。

| Tauri 命令 | 入参 / 返回 |
| --- | --- |
| `list_library_ideas` | → `IdeaSummary[]` |
| `get_library_idea` | `ideaId` → `{idea,references}`，含当前来源状态 |
| `prepare_library_idea_reference` | `input:{kind,asset_id,resource_id}` → 参考预览，必须实际存在 |
| `create_library_idea` | `input:{title,viewpoint,body,references}` → ID |
| `edit_library_idea` | `ideaId,input,expectedRevision` → 同事务更新 |

写入成功发送 `library_changed` 的 ideas scope。工作台摘要增加 `ideas:{items,total}`；备份范围和结果增加 ideas 数量。桌面编辑仍不改写 AI 创建来源；MCP 新建范围见[受控写入](mcp-write-tools.md)。

## 迁移、备份与恢复

schema v1～v10 升级前沿用一致性数据库备份及事务迁移，失败保留旧版本，可重试。逻辑包 writer **v9**，reader **v1～v9**，保留 ideas / idea_references 白名单集合及 ai_source 元数据；旧包缺字段视为空集合，旧版本包夹带选题数据拒绝。

恢复验证自己的正文限制、修订、选题外键、引用唯一性 / 连续顺序、种类与资产身份和名称形状。允许历史缺失引用，现存片段必须仍属于原资产，专题引用不能夹带资产。含 / 不含媒体均保留自己的内容和参考关系，二次备份恢复后身份与顺序不变。只有选题、没有视频的库也属于非空库，不允许被恢复覆盖。

## 验证

Rust 覆盖正文与原文隔离、三类参考、错误归属 / 类型 / 去重、原子保存 / CAS、移除保护、归档 / 重关联 / 缺失后继续编辑、工作台摘要、两轮含 / 不含媒体恢复、恶意包和 schema9→10 回滚重试。浏览器分别检查三视口、三个灵感入口、来源往返、完整冲突副本和读失败；Windows 原生核对生产 Tauri / SQLite / 实际范围播放及空闲重开。实际结果见[第二十七批记录](workbench-knowledge-base-validation.md#第二十七批wb-309-自己的选题和草稿)，macOS Intel / Apple Silicon 继续待验收。
