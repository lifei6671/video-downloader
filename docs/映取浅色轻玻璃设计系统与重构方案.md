# 映取：浅色轻玻璃设计系统与桌面端重构方案

适用产品：映取（Windows/macOS 影音下载器）  
适用仓库：`lifei6671/video-downloader`  
设计方向：**珍珠白底色、雾蓝层次、轻玻璃导航、媒体封面优先、安静精致的桌面体验**。  
交付目标：在现有 Tauri 2、React 19、Tailwind CSS 4、shadcn/ui 基础上统一视觉系统，优化下载作品、任务管理、系统设置与关于软件四个页面，并保留当前实现的业务行为。

## 1. 项目依据和业务边界

本方案基于用户提供的桌面界面截图及仓库 `master` 分支已核对的文件：`package.json`、`src/main.tsx`、`src/style.css`、`src/api.ts`、`src/components/task-removal-row.tsx`、`src/components/video-transcript.tsx`、`src-tauri/tauri.conf.json`、`src-tauri/tauri.macos.conf.json`、`DESIGN.md`、`AGENTS.md`。Codex 实施前仍应读取工作区的最新版本。

项目现状：

- 前端采用 React 19、TypeScript、Tailwind CSS 4、shadcn/ui（`radix-nova`）、Radix 交互组件、lucide-react。
- `src/main.tsx` 集中组织多个页面、下载任务状态和操作；`src/style.css` 已有亮色语义变量，可在此基础上优化。
- `src/api.ts` 封装 Tauri 命令、任务数据与任务事件；Rust 是任务状态权威。
- 默认窗口 1440×900，最小 1024×680，使用原生窗口装饰 `decorations: true`；macOS 最低兼容 13.3。
- 当前 `DESIGN.md` 是项目视觉设计来源，实施时应按本次定稿方案同步更新其令牌、布局和状态规范。保留 `docs/ui/` 既有参考素材。

**业务范围**：保留分享链接解析、引擎选择、视频格式选择、图集、封面预览/保存/复制、队列、下载进度、下载取消与重试、重复下载提醒、历史管理、文件定位/播放、视频文案提取、各平台账号与运行依赖、Telegram 实验模式、托盘与单实例等既有能力。用户操作继续复用现有 API、状态模型和动作条件。视觉重构不需要更改 Rust/Python/SQLite 协议，也不引入独立播放器或暂停、断点续传。

**任务与文件操作**：按 [DESIGN.md](../DESIGN.md) 的操作矩阵约定，从列表移除保留文件；删除本地视频或图集时同步移除下载记录。这两项保留直接执行的现有行为；取消任务、重复下载、批量清理历史沿用当前各自的对话框和确认流程。

## 2. 体验定位

核心体验不是商业后台，而是「把喜欢的作品保存到本地」。优先级为：

1. **作品识别**：封面先于技术元数据，标题与作者清楚可见。
2. **下载操作**：分享输入、解析预览、格式选择、开始下载形成明确的操作路径。
3. **过程可见**：下载中突出真实进度与速度，等待中突出队列顺序，失败时持续显示原因。
4. **本地整理**：已完成作品可以快速播放、打开目录、查看图集、复制原链接和处理记录。
5. **桌面质感**：原生标题栏与窗口行为、微弱材质分层、低干扰的主题与反馈。

日常使用以浅色为基础；窗口背景不是一片无边界的纯白，层次由轻微灰蓝区隔、纤细边框、柔和焦点色和作品封面来建立。玻璃质感主要应用于固定导航、浮层和媒体预览氛围，内容列表保持稳定实色以便阅读与滚动。

## 3. 整体布局与信息架构

主导航维持四项：`下载作品`、`下载任务`、`系统设置`、`关于软件`。启动默认进入下载作品。左侧保留品牌标识及本地状态，版本信息可移至较低权重位置。系统标题栏继续使用原生窗口控件。

| 位置 | 推荐规格 | 说明 |
| --- | --- | --- |
| 侧边栏展开 | 188–200px | 浅雾蓝半透明表面，紧凑导航项，保留原折叠机制 |
| 侧边栏折叠 | 56px | 窄窗口按既有断点折叠 |
| 顶部工具区 | 56px 左右 | 标题、搜索与必要状态信息 |
| 主内容边距 | 20–24px；窄窗口 16px | 控制疏密，不在每个模块上叠加大卡片 |
| 导航项 | 高 38–40px | 轻微背景选中态与图标颜色变化 |
| 首页媒体预览 | 横向封面区 40%、信息区 60% | 空间不足时纵向布局；自然滚动 |
| 首页媒体舞台 | 高 300–380px | 清晰主体封面 + 同源弱模糊氛围背景 |
| 常规任务行 | 高 92–104px，默认约 96px | 中密度媒体行，强调封面而非表格 |
| 活跃下载任务 | 高 118–140px | 展示进度、已下载大小、速度和剩余时间 |
| 任务缩略图 | 76×76px 的固定容器 | `object-fit: contain`，保持视频横竖比例 |
| 列表间距 | 6–8px | 轻边框或分隔线；悬停微弱提亮 |
| 独立任务列表 | 内部滚动 | 顶部搜索和平台筛选可保持可见 |

### 页面 A：下载作品

- **未输入**：以简洁输入区为视觉入口，明确粘贴操作与解析按钮。
- **解析中**：在原来的预览区域呈现进度状态或骨架，不构造虚假百分比。
- **解析成功**：大幅封面与真实标题作为中心，作者、平台、时长、格式与大小居次，下载按钮为明确的唯一主操作。
- **图集**：复用现有 `AlbumGallery`，可以切换每张图片、查看原图/高清标识。
- **格式选择**：选项采用清晰的小型分组控件，保留当前 `api.chooseFormat()` 行为。
- **重复下载/错误**：继续使用当前已实现的对话框与任务错误表达。
- **下载目录**：放在页面底部的轻量辅助信息区。

### 页面 B：下载任务

保留当前的平台筛选和本地标题/作者搜索。统计值如「下载中、等待中、已完成」按实际任务数据生成；状态总量默认作为概览，不应在未实现逻辑时伪装成新的筛选功能。

每个任务行呈现：

- 左侧：76×76 的封面容器；封面缺失使用等尺寸占位，布局保持稳定。
- 中部：标题（建议两行内）以及作者、平台、分辨率、大小等优先元数据；长资源 ID 和完整文件路径交给已有操作/必要时详情面板。
- 右侧：任务状态、最常用的 1–2 个操作和可发现的更多菜单。
- 下载中：单独增加 4px 进度条、真实速度及预计剩余时间；合并音视频使用现有 `merging` 状态。
- 文件不可用：区分「历史下载完成」与「当前本地文件不可用」，保留仍适用的历史操作。

避免一屏均为高边框白卡片；使用 **轻表面色差 + 媒体封面 + 少量行间距**，让用户自然扫描作品。

### 页面 C：系统设置

设置页采用浅色分组表单：分组标题、字段标签、输入区域、辅助说明和必要状态。继续保留下载目录、并发数量、各平台 Cookie、代理、User-Agent、运行依赖、Telegram 实验模式等全部设置及实际行为。文案辅助字体最小 12px；重要提示与错误保留可见文本。

### 页面 D：关于软件及更新

保留品牌图标、版本、发布信息和第三方声明等现有功能。用精致的品牌标题区域、轻微信息卡片和清楚的动作按钮组织内容；与主应用使用相同令牌。

## 4. 视觉设计系统：浅色 Radix 色阶

**选择标准**：使用 Radix Colors 的 light 色阶，不在组件里大量直接写十六进制颜色；先将调色板映射为现有 shadcn 语义变量，再由组件消费。

| 语义用途 | 建议映射 | 视觉表现 |
| --- | --- | --- |
| 全局背景 | `slate-1` | 珍珠白色调，稳定、通透 |
| 主内容表面 | `slate-1` 或 `slate-2` | 平整低干扰 |
| 侧边栏/次表面 | `slate-2` | 微弱雾蓝灰层次 |
| 悬停区域 | `slate-3` | 可感知但克制 |
| 选中背景 | `blue-3` | 轻蓝薄雾 |
| 分割线/边框 | `slate-6` | 极细分隔 |
| 输入边框 | `slate-7` | 清晰的可交互轮廓 |
| 正文/主标题 | `slate-12` | 深石墨文字 |
| 辅助文本 | `slate-11` | 中性蓝灰 |
| 主要按钮/强调 | `blue-9` | 干净的品牌蓝 |
| 键盘焦点 | `blue-8` | 明确的焦点环 |
| 已完成 | `jade-3` + `jade-11` | 柔和成功状态 |
| 等待/文件不可用 | `amber-3` + `amber-11` | 稳定而清楚的警告 |
| 错误/危险操作 | `red-3` + `red-11` | 清晰的错误与删除状态 |

**透明材质**：在侧边栏可使用以 `slate-2` 为基础的高不透明度背景，配合 12–18px 的适度 `backdrop-filter`，右侧内容保持实色。媒体预览内的背景氛围可使用同一张封面微弱模糊，但必须独立裁切与限制重绘面积。弹窗使用可读性更稳定的浅色实底或高不透明度表面；窗口本身不依赖玻璃效果才能正常使用。

**字体**：严格控制为 12px 辅助、14px 正文/任务标题、20px 页面主标题三阶；字重使用 400、500、600。Windows 优先系统 Segoe UI / 微软雅黑等实际可用字族，macOS 优先系统字体；数字使用 `tabular-nums`。

**间距**：4、8、12、16、20、24、32px。**圆角**：按钮/输入 8px，媒体区域和主要分组 12px，预览大舞台 14–16px。**边框**：按项目约定优先 0.5px；需在不同显示缩放上检查实际渲染。**阴影**：仅悬浮菜单、对话框和重点媒体区域使用。**动效**：一般 120–180ms，暂态浮层约 180–250ms，支持 `prefers-reduced-motion`，下载进度高频更新不附加多余动画。

## 6. 任务状态视觉与交互矩阵

| 当前数据状态 | 呈现方式 | 现有操作 |
| --- | --- | --- |
| `parsing` | 媒体骨架与解析状态 | 取消 |
| `ready` | 完整媒体封面、格式与下载操作 | 下载/后台下载、重复下载提醒 |
| `queued` | 浅琥珀状态、真实队列位置 | 取消；Telegram 等待解析说明 |
| `downloading` | 蓝色 4px 进度条、大小、速度和 ETA | 取消，进度持续更新 |
| `downloading` + `merging` | 合并状态，不确定进度 | 延续当前取消行为 |
| `completed` | 封面和浅绿色完成标识 | 视频播放、图集查看、打开目录、提取文案等 |
| `failed` | 持续显示错误摘要，红色状态 | 重试或重新解析 |
| `canceled` | 中性取消标识 | 依据现有条件重试或重新解析 |
| `completed` + `file_missing` | 同时体现历史已完成与当前文件不可用 | 保留适用历史操作、已保存文案 |
| `cover_error` | 稳定封面占位及必要提示 | 不改变真实下载状态 |
| `cache_hit` | 次级缓存标识 | 解析缓存与已下载状态分开 |

下载状态和文件可用性是两个独立维度。不能为“视觉完整性”虚构下载数字；`Task` 未提供的大小、速度和预计剩余时间显示未知或 `—`。视频播放继续调用 `api.play()`；图集查看继续走 `AlbumGallery`；提取文案与封面操作继续沿用已有实现。

**操作可达性**：主要操作在任务行可见，其他操作收纳在更多菜单中；所有现有按钮的显示条件、禁用条件、错误反馈与焦点恢复要保留。图标按钮有中文可访问名称，菜单具有可见焦点样式；删除危险操作按当前直接执行语义完成。

## 7. 工程实施边界

建议以小范围组件切分提高可维护性，不增加新的全局状态框架：

```text
src/
  main.tsx                     # 保留任务状态权威衔接、事件订阅和动作协调
  style.css                    # 浅色 Radix 令牌、shadcn 映射和全局排版
  components/
    media-preview.tsx         # 首页媒体预览（按必要性抽取）
    task-list.tsx             # 任务列表容器、滚动与数据呈现
    task-row.tsx              # 媒体任务行
    task-action-menu.tsx      # 任务操作的菜单表现
    task-removal-row.tsx      # 沿用既有移除动画生命周期
    video-transcript.tsx      # 沿用既有文案处理功能
    ui/                        # 复用已存在的 shadcn/ui
DESIGN.md                      # 更新为统一的浅色轻玻璃视觉规范
```

这些路径是建议切分，不要求为每个组件机械建文件。保留 `mergeTasks`、`revision`、`removedIds`、退出动画与 API 事件顺序。当前 67 条历史任务以普通列表足够，优先检查实际性能后再评估虚拟列表。

### Windows / macOS 窗口外观

- **Windows**：保留原生窗口装饰，匹配浅色标题栏与应用内容的明度；可以在已验证的 Windows 11 环境下尝试 Mica，但它应是可选的窗口外观增强。
- **macOS**：保留原生窗口控制按钮。系统侧边栏材质可以作为适用平台的增强能力；当前项目兼容 macOS 13.3，统一布局和可读性应建立在普通内容表面上。
- **跨平台**：主题令牌和组件布局共用，窗口装饰与材质能力在平台适配层处理，不在业务组件中散布大量平台判断。真实桌面 GUI 验收与浏览器预览分别记录。

## 8. 实施阶段

**阶段一：视觉令牌与任务页**

读取工作区规范与源码、检查 Git 变更；完善 Radix 浅色主题与 shadcn 语义变量。优化侧边栏、标题区与搜索；将任务卡片改造成带封面的中密度媒体行；统一状态、进度和更多菜单。完成筛选、搜索、任务移除、下载进度和菜单操作的回归验证。

**阶段二：首页与其他界面**
