## M1 — 资产模型、数据迁移、库身份与读写角色

**目标**：先让视频资产不依赖下载历史存在，并在 Rust 后端建立明确的主/恢复设备权限。

### 实施内容

1. 增加 `backup_spaces`、`media_assets`、`asset_local_files`、`asset_remote_objects`、`asset_transcripts`、`backup_operations` 以及稳定 `device_id`。字段、唯一索引、外键与状态语义参见主方案第 3 节；建立数据库版本迁移和幂等初始化。
2. 给 `Task` 增加向后兼容的可选 `asset_id`；为完成且有效的视频任务建立资产关联，老记录允许复用 `Task.id`。排除图集、未完成和预览任务。
3. 迁移已持久化转录到 `asset_transcripts`，其关联身份从路径/修改时间扩展为视频内容摘要。原 `video_transcripts` 及现有 `Task` 序列化必须继续可用。
4. 清理任务历史时保留资产、资产文案和本机已完成的视频；若视频和转录内容已经关联资产，删除原下载任务前必须完成持久保存。
5. 持久化备份角色 `primary/reader`、备份空间 ID、库 ID 和写者身份。创建库、连接库的 Rust 路径必须区分；恢复设备后端方法强制拒绝所有 S3 写操作。
6. 写单元测试用的对象存储接口/替身。后续各阶段复用统一对象接口，不引入无业务价值的通用多云层。

### 推荐修改点

- `src-tauri/src/backup/model.rs`、`repository.rs`、`mod.rs`（新增）
- `src-tauri/src/desktop_core.rs` 的 `Task`、`Core::open`、`publish`、下载完成路径、`remove_history_records`
- `src-tauri/src/transcription.rs` 的持久化及查询适配
- `src-tauri/src/lib.rs` 的模块接入

### M1 验收

- [ ] 从旧 `download_tasks` / `video_transcripts` 打开数据库，任务、封面、播放路径和已有文案保持可读取；第二次迁移没有重复资产。
- [ ] 同一完成视频可通过 `asset_id` 获取，清理下载历史后资产及文案仍存在；用户下载文件仍在原路径。
- [ ] 已完成图集或未完成下载不进入视频备份队列。
- [ ] 向后兼容的 `Task` 反序列化、原重试和取消测试全部通过。
- [ ] `reader` 下模拟调用所有远端写方法均返回权限拒绝，模拟对象存储收到 0 次写请求。
- [ ] `device_id` 重启稳定；不同数据库拥有不同设备标识；同一 `asset_id` 可在不同设备独立存储本机路径。

## M2 — S3 客户端、R2 设置与自动备份

**目标**：主设备从已完成视频生成可以被新设备发现的完整远端记录。

### 实施内容

1. 增加官方 Rust `aws-sdk-s3` 客户端，单独封装读写、条件写、分片和删除方法。按 R2 实际支持情况配置 Endpoint、Region `auto`、路径样式、请求校验和、TLS 与 SDK 功能开关；依赖版本写入锁文件。
2. 实现密钥保存/轮换/清理与脱敏回显。`save_backup_settings` 只把 Secret 传给 Rust 并写系统凭据，数据库只存引用；失败回滚新凭据引用，不删除仍被有效配置使用的旧凭据。
3. 实现备份空间：主设备对固定入口 `<prefix>/library.json` 执行 `If-None-Match: *` 创建并回读，已有库先验证 `library_id` 和 `writer_device_id`；恢复设备连接只执行读取。
4. 设置页测试连接使用未保存草稿，验证目标读取连接与已有库身份；不保存配置、不创建库、不写探针，主设备新空前缀允许连接成功，只读设备要求库已存在。已保存空间的后端写探针仍限定前缀随机键，写入→读取→删除且清理失败持久化，供专项验收使用；恢复设备始终只读。不得把草稿测试通过视为已验证写权限。不要调用 Bucket 创建/删除或依赖账户级管理权限。
5. 下载完成文件提交后保证资产映射与待备份操作入队；重启补扫历史完成视频。补扫只读取应用记录，不枚举任意文件夹。
6. 上传流式视频、可用封面、转录。100MiB 以上使用分片，初始分片大小 16MiB；保存 `upload_id`、分片 ETag 和源摘要，重启 `ListParts` 对账。源文件变更则停止发布记录。
7. 视频使用不可变对象键 `media/<asset_id>/<content_sha256>/video.<ext>`；小对象上传完成后才使用 `If-None-Match` 或 `If-Match` 发布 `records/<asset_id>.json`。封面从已存在的 SQLite 缓存读取，缺封面不阻止视频成功。封面和转录的路径额外包含自身内容 SHA-256，更新不覆盖旧记录引用的对象。
8. 实现有界重试、`429` 限速、配置/认证错误阻断、取消与重启恢复。后台上传初始并发为 1，不能占用现有下载并发上限。

### 推荐修改点

- `src-tauri/src/backup/s3_client.rs`、`scheduler.rs`、`repository.rs`、`model.rs`
- `src-tauri/src/settings.rs` 或独立 `backup/settings.rs`
- `src-tauri/src/desktop_core.rs` 的下载完成及启动补扫
- `src-tauri/Cargo.toml`、`Cargo.lock`
- `src-tauri/src/desktop.rs` 的脱敏配置与连接检测命令
- `src/api.ts` 的类型与配置接口

### M2 验收

- [ ] 首次创建库只成功一次；两次同时创建仅一份 `library.json`，另一请求识别 `412` 并回读。
- [ ] 空间身份不符、凭据缺失、权限不足均显示明确错误；普通设置返回及事件不含 Secret；专用编辑回填接口除外，默认掩码且不持久化到前端存储。
- [ ] 完成视频本地立即可播放；备份失败时 `Task.status` 不被改成失败。
- [ ] 下载完成后立刻退出，重启能补录未入队备份；重复重启不重复创建资产。
- [ ] 单次上传和分片上传均能提交同一正确媒体；网络中断恢复分片，源文件变化和 `NoSuchUpload` 安全重新开始。
- [ ] 完成媒体上传但尚未写入 record 时异常退出，恢复设备列表不可见此未完成资产；主设备重启核验后发布一次。
- [ ] `PutObject` 未知结果和 `CompleteMultipartUpload` 未知结果可通过远端查询对账，不仅按本地异常重复写入。
- [ ] 上传操作在调用异步网络接口时不持有全局核心锁；前台播放/取消仍可响应。
- [ ] 恢复设备测试连接不会发出 `PutObject`、`DeleteObject`、分片创建/完成请求。

## M3 — 只读发现、封面、文案与幂等导入

**目标**：仅使用 Bucket、Prefix 和只读凭据，另一台设备可看到库中的全部有效资产，直接查看已有文案。

### 实施内容

1. 连接时先读取并验证 `library.json`；未知库、版本过高、身份不匹配均拒绝写入与自动导入。
2. 用 `ListObjectsV2` 分页枚举 records，以 ETag 缓存跳过未变化记录；逐条校验 JSON schema、`library_id`、`asset_id`、对象键前缀、媒体大小/摘要及容器类型。
3. 对 `state=active` 创建/更新本地资产，对 `state=deleted` 保留墓碑并禁止恢复。一次网络请求失败时保留已导入的稳定列表，不根据部分分页结果删除资产。
4. 封面按视口需求懒读取；转录文案只请求 `transcripts` 对象，落入 `asset_transcripts`。列表加载、普通刷新、搜索以及复制文案均不请求视频对象。
5. 远端资产数据与普通下载任务保持独立类型，在下载任务列表合并展示；不能为云端资产伪造 `Task.status=Completed` 或填充虚构本机路径。

### 推荐修改点

- `src-tauri/src/backup/reconcile.rs`、`repository.rs`、`model.rs`
- `src-tauri/src/desktop.rs` 的 `list_backup_assets`、`refresh_backup_assets`、`get_asset_transcript`
- `src/api.ts`、`src/main.tsx` 的素材列表最小垂直切片

### M3 验收

- [ ] 两个互不共享 SQLite 的设备连同一测试库，远端 `asset_id` 在两端相同，本机路径各自独立。
- [ ] 首次读取完整清单，多页读取、增量刷新、重复刷新均不重复导入资产。
- [ ] 列表、搜索、预览封面、查看/复制/导出已有文案过程中，模拟存储的视频 `GetObject` 请求数为 0。
- [ ] 未知 JSON 字段可安全忽略；畸形 JSON、非法路径、跨前缀对象键、异常尺寸与未知版本明确拒绝该条目。
- [ ] 遇到删除墓碑，恢复按钮不可用；已下载的其它设备本地视频不被删除。
- [ ] 网络中断、`403` 和真实空库在界面中可区分，不因同步失败清空本地库。

## M4 — 按需恢复、文件提交及播放/转录复用

**目标**：所有视频消费入口先走同一个恢复原语，本地有效时零网络；仅云端时可靠下载、提交、继续操作。

### 实施内容

1. 实现 `ensure_local_video(asset_id) -> PathBuf`：先判断本机受管理文件并校验身份/有效性；本地有效直接返回。
2. 启动云端恢复前读取最新 record 状态，确认活动、库匹配、引用合法，防止仅凭过期的本地缓存恢复已删除资产；最终提交前再次校验本地删除意图，必要时回读远端版本。
3. 用 `GetObject` 流式写目标卷暂存文件，保存对象 ETag/摘要、字节偏移与操作 ID；支持 `Range` 续传，对象版本变化或 Range 不支持时从头恢复。
4. 完成时校验总大小、完整 SHA-256、媒体头和容器；对文件名使用安全规范化和不覆盖提交；持久化文件提交意图，恢复异常重启窗口。
5. 相同 `asset_id` 的多个并发播放/转录请求共享单个恢复操作，不并发写同一目标文件；取消与关闭 UI 不造成迟到自动播放。
6. 将云端资产入口接到现有系统播放、内置播放与 `transcription.rs`；继续复用原识别引擎、模型配置、进度与取消流程。已有远端文案的“查看/复制/导出”无须恢复视频。

### 推荐修改点

- `src-tauri/src/backup/restore.rs`、`scheduler.rs`、`repository.rs`
- `src-tauri/src/files.rs` 的通用安全提交/媒体校验复用
- `src-tauri/src/desktop.rs` 的播放接口
- `src-tauri/src/transcription.rs` 的资产级启动入口
- `src/api.ts`、`src/main.tsx`、`src/components/video-transcript.tsx`

### M4 验收

- [ ] 本机文件校验有效时调用恢复入口返回原路径，S3 视频请求数为 0。
- [ ] 两个播放请求与一个转录请求同时触发，只发生一次实际远端视频下载。
- [ ] 中途断网及重启可以在版本一致时续传；版本不一致必须丢弃不匹配的暂存数据。
- [ ] 文件大小正确但内容摘要不同、无效媒体头、磁盘空间不足均不能标记“本机可用”。
- [ ] 已有同名文件绝不覆盖，成功提交的新文件可播放；已提交文件但数据库尚未更新时崩溃能恢复。
- [ ] 从云端恢复视频后可以走现有内置/外部播放和转录；历史文案不会因恢复路径不同而误判失效。
- [ ] 关闭播放 UI 后完成的恢复只更新状态，不重新打开播放器。

## M5 — 生命周期、墓碑清理与界面收口

**目标**：实现本地文件释放、主设备删除远端、权限约束和清楚的 UI 反馈。

### 实施内容

1. 新增 `release_local_video(asset_id)`。仅删除本机被应用管理且身份核验通过的文件，不影响远端元数据与转录；主/恢复设备均允许。
2. 现有下载任务中“删除视频”若处于主设备已启用的备份空间，应与 `delete_asset_and_backup` 语义一致；未备份、未启用或恢复设备情况下，保持安全的本地删除并明确区分 UI 文案。新增“释放本机副本”，让用户能保留云端内容并回收空间。
3. 主设备删除先持久化意图与所有远端对象键，再中止该资产上传/恢复，删除本机文件、条件写入墓碑、删除远端对象并核验终态。
4. 已有 record 用 `If-Match` 写墓碑；备份待上传、record 不存在时用 `If-None-Match: *` 创建墓碑，`412` 回读再判定。已删除记录不能被旧操作重新发布为 active。远端 404 可作为单个目标对象已不存在处理，权限或网络错误不能伪装成删除成功。
5. 删除完成后保留不含标题/来源/文案的最小墓碑；清理重试和分片只针对本任务可证明拥有的键和操作，不执行整个 Bucket 的遍历删除。
6. 恢复设备后端所有写命令都强制禁止；从任意前端入口调用也返回权限错误。恢复设备遇墓碑后保留本机已下载副本，停止远端恢复。
7. 设置页增加远端备份开关与配置，不增加独立云端主导航；下载任务展示空心云朵待同步、上传字节逐渐填充、成功发布后的绿色对号。从 S3 恢复使用逐渐填充的同步图标，普通下载进度保持原样。远端错误仅Toast反馈，同一错误不随轮询重复弹出；同步按钮直接上传/恢复/取消，不弹出子菜单，覆盖断网待删除和重试。UI 视觉按 `DESIGN.md`，不新建平行组件库。

### 推荐修改点

- `src-tauri/src/backup/repository.rs`、`scheduler.rs`、`reconcile.rs`、`restore.rs`
- `src-tauri/src/desktop_core.rs` 的本地删除和历史关联
- `src-tauri/src/desktop.rs` 的新增命令与事件
- `src/api.ts`、`src/main.tsx` 及现有任务操作组件
- 相关 CSS、测试夹具、适当的专项契约文档

### M5 验收

- [ ] 主设备明确删除的视频，离线时本机删除完成且“远端待删除”持续可查询，联网后墓碑与对象清理完成。
- [ ] 本机文件删除失败时不继续远端删除；本机文件已不存在但用户明确发起云端删除时可继续。
- [ ] 删除/上传交错、元数据写入 `412`、远端对象已不存在、远端删除中断均符合幂等状态机，不复活资产。
- [ ] 任意恢复设备通过 UI 或直接调用 Tauri 写命令，模拟对象存储收到 0 次写请求。
- [ ] “释放本机副本”后从云端可重新恢复；“移除历史”不删除资产或文件；主设备“删除视频及备份”不会误删其他资产。
- [ ] 恢复设备看到墓碑后不自动删除既有本机副本，且不得再次从远端恢复。
- [ ] 三种设计视口、键盘路径、焦点恢复、减少动态效果、取消及错误反馈符合现有 UI 规范。

## M6 — 可靠性测试、真实 R2 与交付证据

**目标**：用可复现的证据证明单主写、只读恢复和删除协议可落地。

### 离线故障注入矩阵

| 测试 | 必须观察到的结果 |
| --- | --- |
| `PutObject` 成功但响应超时 | 重新 `HeadObject`/比对版本，避免再次覆盖与重复发布 |
| `CompleteMultipartUpload` 已完成但客户端断开 | 依据远端现状恢复记录发布，不误报对象丢失 |
| 上传中源文件替换、大小/摘要变化 | 终止或重建上传，不发布错误媒体引用 |
| 主设备上传媒体成功但尚未发布 `records` 时退出 | 只读设备看不到未完成资产，重启可继续 |
| 写墓碑前应用崩溃或断网 | 删除意图和目标键完整保留，重启从相应阶段继续 |
| 墓碑已写但某个对象删除失败 | 只读设备立即禁止恢复，主设备继续物理清理 |
| 读者有旧缓存，主设备已删除 | 读者发起恢复时重新核验最新记录，不提交已删除视频 |
| 写入 `412`、`429`、`403`、`5xx` | 各有正确冲突、退避或阻断策略，错误持续可查询 |
| 改 Endpoint/Bucket/Prefix | 已入队操作保持绑定旧 `space_id`，不误写新空间 |
| 双设备独立数据库 | 同一资产身份、不同本机路径，只读设备没有远端写流量 |
| 释放本机文件与清理任务历史 | 云端保持 active，记录与文案仍可读取 |
| 路径穿越、同名文件、软链接、损坏媒体 | 不覆盖、不越界、不提交不可信文件 |
| 已有下载、图集、转录、封面缓存 | 旧行为回归成功，无非必要改动 |

### 真实 R2 验证

使用**专用测试 Bucket + 独立前缀 + 临时权限凭据**；准备独立的主设备数据目录与恢复设备数据目录。验证创建、上传、重启续传、导入、懒加载、文案访问、恢复、释放、删除、墓碑和再次刷新。后端日志需能证明恢复设备只执行 `GET/HEAD/LIST`，但不得输出凭据或私密链接。测试结束只清理确认为本次测试生成的对象，绝不直接清理真实用户 Bucket。

手动主设备迁移单独验证：停旧设备、撤销旧写密钥并确认权限变更生效、条件更新 `library.json`、新主设备持新写密钥启动，旧设备重新上线写入被拒绝。**未验证撤销旧写凭据之前，不承诺同一空间的接管具有强互斥性。** 首版允许提供有审计步骤的操作文档或安全命令行辅助工具，不要求图形化向导。
